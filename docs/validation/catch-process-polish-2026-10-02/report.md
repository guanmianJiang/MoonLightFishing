# 钓获处理动作与水滴衔接复核（2026-10-02）

## 本轮实现

- 规格先更新 `docs/design/catch-process-feedback-spec.md` 第二版及 `docs/design/scene-water-spec.md` 的范围可见规则。
- 处理开始接管上一帧经过 IK 约束的手、肘、竿角和身体倾斜；右手独立前伸，再按实际落水时刻收回。移除原来长达 1.7 秒的放流正弦手势，视线跟随钓获。记录保留托举，收藏/入篓有右手下收。
- pending 清空后，处理阶段仍隐藏抛竿范围、落点、临时圈和闲置钩饵。开始时清理旧指针；画布点按/拖动/双指缩放及滚轮在处理期间暂停，结束恢复。
- 水滴仍使用原有 48 个网格池，单次最多 24 个。半径降到 0.010–0.022 m，用 11.8 m/s² 的解析重力和速度方向拉伸；落回水面就回收。按实际帧时间采样，慢帧不拖慢下落，没有新 shader、贴图或常驻 draw call。手部快照向量复用。

`npm test`：**642 / 642 通过**；`npm run build` 与页面、模型、音频等构建资源检查通过。日志：[tests.txt](tests.txt)、[build.txt](build.txt)。

新增测试直接执行实际场景的 IK 衔接段、画布指针处理器和水滴池更新段；验证首帧手坐标保持、关节有效、处理期间手势被阻止、随后触控可恢复、迟到帧回收水滴。纯函数测试覆盖前伸时序、连续收势、减少动态、非法时间、收藏/记录差异、水滴加速度、精确落水、强度及随机数限幅。范围规则测试覆盖近景与顶视处理状态。

## 一致性与待验

规格、实际动作代码及测试一致；已有咬实取景与处理音效规格仍由各自模块负责。全部新路径为仓库相对路径。临时页面、验证标签页和测试服务已清理，浏览器画幅恢复。

本轮沿用原有模型、水体、光照；未重制资产。实际手机扬声器、振动和主观手感未验，浏览器 PCM 仅证明输出链路。低端移动设备需保持原画面设置，连续比较 60 秒抛竿/放流前后的帧时间与 draw call，检查 20 次处理后的内存、后台恢复、静音及减少动态设置；不能把桌面截图作为移动端性能验收。
