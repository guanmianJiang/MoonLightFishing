# 天际线硬线、HDR 与倒影开销复核

日期：2026-10-01；版本：`2026.10-sky-background-depth`。按用户要求只使用源码、资源查看和离线检查，未操作电脑界面。

## 确定的缺陷与修正

天空球为半径 1600 米的有限球面；相机远裁剪 16000 米，远水约 12000 米。原天空默认顺序 0、深度测试开启，只禁止深度写入；海床顺序 -2、水 -1，因此天空之后画且在球面外的水/地形前面通过深度测试。这可造成水平边界/球面多边形边缘，并使捕获颜色被天空覆盖而地形深度未变。

`src/scene.js` 为天空设置 `depthTest:false,depthWrite:false`，`sky.renderOrder=-3`，在海床/水前绘制。不扩大球、不改贴图/采样/雾强度/水参数、不增加模糊。天空空白像素的深度仍是清除值 1，后画的地形和水留下自身深度。

查看当前天空02资源未发现截图那样的多段直线。截图位置与上述深度问题相符；没有 GPU 重放，不能将此写成截图每一条线的唯一归因，也不能宣称已视觉消除所有线。

## HDR 合同

| 层 | 源码事实 | 含义 |
| --- | --- | --- |
| 色彩选择器 | 太阳/泡沫/空气颜色和水色渐变均为六位 HEX，原生 color 输入 | sRGB 基色，缺少逐色独立 HDR 能量倍率 |
| 线性处理 | Three Color 自动转换 HEX 到线性工作空间；天空纹理标记 sRGB | 颜色正确解码，但普通颜色/PNG 并不因此获得高动态光照数据 |
| 场景/捕获 | 后期主目标、Bloom 两目标、水捕获均 HalfFloatType；捕获和主通道临时关闭色调映射 | 已有 HDR 中间管线，可存大于1的能量 |
| 光照与最终输出 | 太阳色乘天气光强（晴天2.65），水面高光加法；最后合成执行色调映射和输出色域 | 可以产生HDR亮部，当前页面显示仍为普通sRGB输出，未配置显示器HDR输出 |
| 天空环境 | 六张8位PNG全景 | LDR天空，未加载EXR/RGBE环境动态范围 |

本轮不新增颜色/曝光/HDR控件，也不改用户已发布调色。水体、泡沫等基色不应统一提升成发光强度。太阳/环境能量控制与导入 HDR 天空是不同需求，应另立规格。

## 倒影成本

- 天空倒影：每个水片元一次全景纹理查询，反射方向/菲涅尔/高度空气层运算；没有六面相机或镜面重绘。
- 岸边倒影：SSR 复用现有捕获；每个参与片元最坏 12 次深度步进、3 次细化、1 次命中色采样。未命中/出屏/背向会早停，不能用最坏值宣称所有像素都走满。只追踪有限附近路径，屏幕外物体不可见。
- `reflectionSceneStrength=0` 确实跳过追踪；非零倍率降低仅改变混合量，不降低步数。反射总体强度0也使主混合处跳过物体追踪，但当前天空查询仍存在。折射捕获仍每帧执行，关闭SSR不会关闭这遍场景绘制。
- 捕获尺寸为 `rw=min(1600,floor(w*min(DPR,1.5)))`、`rh=max(1,floor(rw*h/w))`。以390×844、DPR≥1.5为例是585×1266；RGBA16F颜色8字节+深度按4字节估算约8.48MiB，不含驱动填充和其他目标。后期主目标另有最多4倍MSAA与两个半分辨率Bloom目标，整个画面开销不能都归给倒影。
- 无 GPU 计时或真机测量，不提供毫秒、FPS下降或GPU占比结论。低端设备先比较物体倒影0与当前非零值各60秒，再分别观察分辨率/Bloom/MSAA；保留天空镜像。
