# 下一竿线索回响规格

## 目标

在现有选点、抛竿、自然鱼口、钓获处理和手记流程中，让一次结果给下一竿留下可理解的观察方向。十分钟竖屏试玩应能从一竿的结果，看见下一竿可验证的线索，并在等待水面时再次感知它。线索不是必中承诺，也不增加货币、评分或限时操作。

## 数据结构与接口

- `src/next-cast-thread.mjs` 提供纯函数 `nextCastThread(save, weatherId)`，读取现有 `waterTrail`、`tracked`、`clues`、`log`、`spot`、`bait` 和探索进度；返回 `{kind,title,detail,waterLine,action}` 或 `null`。`action` 是选点、换饵或瞄准指令。不新增存档字段。
- 优先级：刚失手留下的鱼讯、新水域解锁、当前水域的放流追踪、已有水域线索。仅当对应条件仍有效时展示；未知或损坏字段安全降级。传入天气时，鱼讯还需通过当前抛竿权重资格检查。
- `src/config/fishing-tuning.mjs` 汇总新抛竿的鱼群权重、鱼饵/水域修正、等待时间和搏鱼前的重量修正。数值迁移先保持现行行为；已有 `pending` 不重算。

## 输入输出与体验

- 准备态的路线卡显示下一竿线索和可执行的选点、换饵或瞄准动作。玩家仍可自由选择其他钓点。
- 处理钓获或空钩后，水边观察文字说明本竿结果，准备态路线卡给出下一竿方向；失手鱼讯也会在水边观察文字中出现。安静等待时只出现一次与该方向一致的轻量水面提示和局部涟漪。
- 放流后的追踪提示说“可能再次遇见”，失手鱼讯说“下一竿同钓点同鱼饵可能追到”；不得宣称必然出现。沉水物不生成活体追踪。
- 首次抵达栈桥或深水时，优先引导观察新水域；重复钓获不无限堆叠提示或弹窗。

### 十分钟可玩路径

1. 从近岸选麦粒并抛第一竿，观察浮漂；获得钓获时可做记录或放流，失手时形成只保留到下一竿的鱼讯。
2. 回到准备态，路线卡给出一个与刚才结果对应的下一竿方向；玩家点卡片动作进入选点/换饵，再单独确认抛竿。
3. 第二竿等待时，水面只给一次相应的细纹提示；鱼是否回游仍由现有抽取决定。失手鱼讯在此次确认抛竿后消耗，不继续承诺。
4. 放流过的活体可在同一水域形成追踪期待；调查与钓获积累达到门槛后，路线卡转向新水域。手记保留已学到的鱼种习性和水域线索。
5. 试玩时允许自由选择处理方式与钓点，不用固定脚本替玩家完成二十竿。记录玩家自行决定再抛的原因和中途退出点。

## 边界与异常

- 旧存档不迁移新字段；刷新后由当前存档重新推导线索。
- `waterTrail` 只对下一次抛竿有效，消费后不得继续显示追踪承诺。
- 线索已满足、钓点不可达、没有有效内容时回到现有路线引导。玩家操作、随机抽取、鱼口宽容度和结果结算保持原规则。

## 验证

使用 Node `node:test` 覆盖鱼讯、放流、解锁、普通线索、损坏存档与消费后回退。检查 390×844 和 320×568 准备、等待、结算、回流画面，真机核对触控、音画与低端设备帧率。十分钟试玩记录玩家在第 4、8、20 竿是否能说出下一竿想验证什么。
