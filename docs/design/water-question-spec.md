# 自选水情问题规格

日期：2026-10-02。状态：P0 小切片。承接 `HANDOFF.md` 的“带着自己的想法再抛一竿”，只使用已有本轮水域事件、鱼池、钓点、鱼饵和近远落点。

## 目标

准备态保留已有“沿上一竿线索”主方向，同时让玩家可选一个不同的、本轮水情支持的问题。点选问题会备好对应钓点和鱼饵，进入落点预览；玩家仍要亲自确认抛竿、看鱼口和搏鱼。结果只根据本竿实际带上岸的东西回答，不把随机抽取说成规律已被证明，也不给必中、加成、领奖或任务失败。

## 配置与数据

- `src/config/gameplay/water-questions.json` 存储固定 `id`、对应的 `ruleId`、条件 `spot/bait/zone`、可验证活体鱼 ID、问题标题、等待提示与结果短文案。首批分别对应浅滩鱼群、底层食物和捕食鱼；需要未开放钓点的问题暂不提供。配置需校验目录引用、唯一 ID、区域、文案和目标鱼是否在该条件下有正抽取权重。
- `src/water-question.mjs` 的 `waterQuestion(save)` 返回当前可选问题及一步进入瞄准的动作；`waterQuestionCastId(save,selectedId)` 在玩家确认抛竿后核对实际 `pending` 的钓点、饵、区域、本轮规则，输出 ID 或 `null`；`waterQuestionOutcome(pending)` 只在 `pending.phase==='result'` 时根据已保存 ID 和实际上岸钓获输出 `matched / other / unresolved` 与短句，不能提前泄露抽中的鱼。纯业务函数不读 DOM、设备时间或随机源。
- 本竿 `pending.waterQuestionId` 可缺省。仅玩家主动点选后且最终确认的条件仍匹配才写入；刷新中的既有抛竿保留快照。旧存档缺字段按未选择处理，不补造历史意图。
- 本轮 `trip.moments` 可在真实结果中保存 `{waterQuestion:{id,status}}`，仅 `matched` 可成为一轮回顾的一个候选记忆；重复处理和无效 ID 不追加。

## 玩家流程、输入与输出

1. 首竿不开第二选择。之后准备态展开路线卡，可在原主方向与“试试本轮水情”之间主动选择；第二选择显示问题和对应条件。短屏卡片可滚动，两个入口触控高度至少 44 像素，不盖住抛竿确认。
   浅滩原型中，上一竿麦粒鱼讯与水情问题使用不同鱼饵；选择换饵会按现有规则消耗单竿鱼讯，不能暗中同时享受追鱼加成。问题针对具体鱼种，单竿命中有悬念。
2. 点水情问题只设置已解锁的钓点、鱼饵并进入相应近/远水预览。玩家可改选落点、取消或自由换饵；若最终条件不符，不记为答过这个问题。
3. 抛竿与搏鱼完全使用现有规则。安静等待时给一条与本次问题一致的水边观察提醒，不凭空宣称鱼已靠近。上岸目标鱼只说“这次符合判断，还值得再看”；上岸其他活鱼说明实际遇见什么；沉水物或空钩说明本竿没有足够证据。一次真实结果只记一次，不从隐藏抽取或失手推断玩家已经辨认鱼种。
4. 结果处理后的水边短句回响此问题；已有重大观察发现仍可优先成为 toast。本轮回顾若没有更重要发现，可记住一次玩家主动选择且得到符合结果的尝试。问题可以再试，不成为强制目标。

## 边界与异常

- 当前本轮规则缺失或未知、配置错误、目标钓点未解锁、第一竿、抛竿中、轮次结束、不合法落点及未知旧 ID 均安全回退到原路线，不写意图。
- 临确认前取消或切换条件会撤销匹配；刷新后的既有 `pending` 只消费存下的有效 ID。处理动作、失败、复盘和重复读取均不改变鱼池、天气、鱼口、提竿窗口、经济与现有发现证据。
- UI 只增加已有卡片内的文字和按钮，不增加模型、纹理、draw call 或 shader。390×844、320×568 竖屏验证入口、选点、结果及回流；真实手机检验触控和玩家是否理解“两个方向都可以选”。

## 验证

Node `node:test` 覆盖配置引用与抽取可达性、三种本轮规则、首竿/锁定水域、条件改变、真实上岸/其他鱼/挂物/空钩、旧存档、刷新快照、重复结算及回顾优先级。构建与实际竖屏流程核对。
