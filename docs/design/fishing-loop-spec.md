# 垂钓流程与存档规格

> 状态：源码已恢复，逻辑测试已运行；浏览器交互仍待验收。依据 `src/engine.mjs`、`src/data/catalog.mjs`、`src/config/game-rules.mjs` 和配套测试维护。

## 目标与范围

玩家选择钓点和鱼饵，抛竿、观察咬口、提竿、搏鱼，最后记录、放生或按当前测试所述放入鱼篓。单次抛竿的结果在刷新后保持稳定。长期进度保存在设备本地。读漂阶段以 3D 浮漂、鱼线和水面为主体，不再弹出限时三选一答题。

`HANDOFF.md` 将个人探索列为产品方向，并反对售卖升级循环；`README.md` 和现有测试则记录了鱼篓、金币、出售、升级。此产品分歧尚未决策，维护时不得将其中一方默认为最终设计。

## 数据结构

- 存档至少包含钓点 `spot`、鱼饵 `bait`、抛竿计数 `casts`、当前抛竿 `pending`、探索进度及 `economy`。现有测试引用钓点 `reed`、`bridge`、`deep`。
- `pending` 至少具有 `start`、`decisionAt`、`readyAt`、`signal`、`catch` 等字段；新抛竿设 `biteMode:'natural'`。`decisionAt` 是鱼开始试探的时间，`readyAt` 是鱼真正咬实的时间。读漂、提竿与结算须围绕同一结果运行。
- `economy` 至少具有 `coins`、`basket`、`upgrades`。旧存档迁移时需补齐缺失字段且保留已有探索进度。
- 本地键 `moonwater-v1`、存档版本、最近钓获上限、每轮竿数与读漂时间由 `src/config/game-rules.mjs` 定义。界面显示条数仍需单独核对。

## 接口与输入输出

`src/engine.mjs` 对外保留 `newSave`、`migrateSave`、`makeCast`、`finishCast`、`processCatch`、`startNextTrip` 等函数；旧 `chooseTactic` 仅供旧存档和兼容测试，不再由游戏界面调用。原有目录数据导出从 `src/data/catalog.mjs` 转发。`src/fishing-motion.js` 提供 `phaseOf`。输入是存档、时间、玩家动作与可注入随机源；输出是更新后的存档、抛竿状态或结算结果。可注入随机源使结果可复现。

`src/reel-transition.mjs` 的 `shouldStartLanding(pending, revealing)` 输入当前抛竿和演出标记，仅当 `pending.phase==='cast'`、搏鱼已获胜且未在演出时返回 `true`；缺失抛竿、已结算或正在演出时返回 `false`。`finishReel` 自身也以 `cast` 阶段为入口条件，避免外部重复调用绕过判断。

新抛竿按准备、飞行、等待、鱼影试探、鱼嘴靠近、咬实、搏鱼或空钩、结算流转。`signal` 决定试探期的鱼影和水纹，不决定正确按钮。试探到咬实自动推进，只有咬实后的提竿是玩家动作；没有鱼或错过宽松的提竿窗口则自动收回空线。咬实时显示与搏鱼阶段同一个右下“按住 + 上抬”触控区，按下即提竿，保持按住直接收线；松手让线，合适时机上划带鱼并滑回收线。上划时按压键留在原处，两条细张力线随距离向上伸展，松手后回缩淡出。不显示单独的“开始提竿”按钮或数字倒计时；近景触摸浮漂附近仍可提竿，但必须保留同一个大触控区作为可靠入口。空钩仍自动回收，不要求按这个触控区。

### 沉水物与活体分流

- 以目录项的 `object` 属性识别瓶子、铜铃等沉水物，不靠固定 ID。未知或无钓获不按沉水物处理。
- 沉水物等待期没有鱼影、试饵和主动冲刺；到点后浮漂只短促下沉并保持轻微静态负重，不周期横游、反复水花或触发鱼咬钩的强振动/音效。提示为“钩上似乎挂了东西”，避免提前揭晓物品。
- 右下触控区对沉水物显示“收回”，点按一次直接进入平稳收线与出水展示，不创建搏鱼状态、鱼种习性、冲刺音效、抬竿/让线手势、搏鱼评级或鱼讯追踪。底部入口与近景浮漂点按走同一收回动作，重复点按不得重复结算。
- 沉水物不会自行挣脱，不适用活体提竿窗口超时；刷新后仍可从挂物状态收回。收线保留物体重量、钓线受力和入水/出水小水花，但不使用活体横摆与挣扎脉冲。结果页按沉水物名称、描述和重量展示。

### 连续垂钓节奏

#### 咬钩反馈时序（2026-09-29）

- `readyAt` 是鱼嘴碰到钩饵并咬实的视觉与逻辑边界。此前 `reading`、`responding`、`nibble` 只表现鱼体接近、鱼身附近水纹和玩家主动提饵/收线动作；浮漂保持环境波动，不自动下拽、横移或倾斜，也不在浮漂旁制造接触水花与负载张力。无鱼和沉水物同样不得提前表现活鱼拉漂。
- 到达 `readyAt` 后才由 `hookedBobberMotion` 从零负载平滑建立下沉、倾斜和鱼线张力。阶段文字与画面一致；边界时间无位移跳变。无效时间和未知鱼讯回退为平稳浮漂。

#### 轻提鱼饵与鱼影回应（2026-09-30）

- 自然鱼口从鱼影出现的 `approach` 到 `reading` 阶段，玩家可轻点浮漂附近一次，做一记很轻的提饵。约 5 秒的可操作时间让玩家先看到鱼影再尝试；操作是可选的，不能成为限时答题或钓获前置条件；临咬钩的 `nibble`、其他阶段、沉水物、空钩和远离浮漂的触点不触发。
- 成功轻提在当前 `pending` 记录 `teaseAt` 和 `teaseCount=1`；同一竿重复点按不叠加收益。浮漂/钩饵只短暂**向上**移动，竿尖同拍轻抬，鱼影在约 0.4 秒内逐渐缩小与鱼饵的水平距离。效果起点为零、鱼嘴到钩点时回到零偏移，不得出现咬钩前自动下拽或鱼体跳位。鱼种、鱼重、`readyAt` 与抽取结果不改变。
- 第一记有效轻提为该竿增加 1 秒提竿宽限，让玩家看到鱼影回应后有余裕操作；原有宽限仍生效。点击立刻提供很轻的音触反馈。鱼影靠近和读鱼影阶段底部栏隐藏，因此复用画面上方的鱼讯提示卡说明“轻点浮漂可轻提鱼饵”；成功后改为“鱼影跟近了，等它咬稳”，不新增大型按钮或覆盖浮漂。刷新后轻提次数与宽限保持，瞬时动画按时间自然结束。
- 纯逻辑测试覆盖有效/无效阶段、重复触发、旧存档、窗口幂等、运动起点/终点和鱼嘴到钩点连续性；竖屏视觉检查玩家动作、鱼影与浮漂的先后关系。
- 提饵幅度、鱼影跟近比例、动画时长和提竿宽限集中由 `src/config/fishing-tuning.mjs` 的 `LURE_TEASE_TUNING` 调整；场景只消费同一组参数的运动结果，不在渲染层另写一套时长。

#### 鱼影到咬实的镜头节奏（2026-09-30）

- 自然鱼口的 `approach` 从鱼影初现起进入水面观察镜头：先用很轻的推进引导视线到浮漂附近，鱼影与浮漂的实际间距缩小时才进一步靠近，到 `reading` 形成较近取景，随后在 `nibble` 到咬实前退回能同时读到浮漂、竿线和人物的等待构图。9:16 短屏的试饵镜头不可把浮漂放大到让鱼影离开画面或人物完全消失；镜头靠近上限、鱼影距离响应与视角由同一配置控制。位移、注视点与视角必须连续，不能在阶段名称切换时跳帧，也不能提前用突然的下沉或镜头猛推宣称已经咬钩。
- 玩家在 `approach` 或 `reading` 有效轻点浮漂时，复用现有短促镜头回应；重复轻点、沉水物、空钩、俯瞰态和咬实后不触发这段鱼影观察镜头。镜头仅消费现有 `decisionAt`、`readyAt`、鱼口阶段和轻提时间，不改变物理、提竿窗口、随机结果或存档。
- 纯逻辑测试约束从鱼影初现到观察、退回的权重连续且有界，阶段优先级和旧存档缺失时间的行为稳定；浏览器按 390×844 与 320×568 观察鱼影、浮漂与人物构图，真实手机验证触屏轻提后的镜头响应与低端设备帧率。

首次抛竿另见 `docs/design/opening-cast-spec.md`：全新存档默认近岸麦粒首竿缩短到约 7–9 秒出现鱼口、筛选为浅水常见鱼、使用轻型鲫鱼个体，基础提竿窗口 16 秒，近水仍加 2 秒。第二竿与旧存档维持下列普通抛竿节奏。首次咬实只补充一句触控提示，不新增必中钓获或倒计时。

- 新抛竿的咬实时间以 `castWaitBaseMs=9000`、`castWaitRandomMs=4000` 计算，落点仍可加减 700 毫秒。已有 `pending.readyAt` 是存档事实，更新节奏时不得重抽或改写。
- 等待期的环境提示只在真正的安静阶段出现，临近鱼讯时交给鱼影和局部水纹表达；咬实后才由浮漂和鱼线表达受力。提示不得随机宣称鱼已靠近，避免和实际鱼讯矛盾。
- 空钩或脱钩在收线演出完成后由 `settleEmptyCast` 一次性记竿、结算并清除 `pending`。水边文字短暂说明原因，直接回到临水准备态，不弹空结果窗，也不要求再点“继续”。最后一竿仍展示本轮摘要。
- 钓获仍打开结果窗，由玩家决定记录、放流、收藏或入篓；完成决定后回到临水准备态，保留可切俯视的入口。刷新恢复的空结果同样自动结算，已处理结果不得重复扣竿。
- 搏鱼胜利后的提鱼演出只在当前抛竿仍为 `cast` 且尚未开始演出时触发一次。演出结束将 `pending.phase` 置为 `result`、停止收线音效并展示结果窗；等待玩家处理期间，周期更新、窗口恢复或刷新均不得再次启动收线演出、振动或结果音效。玩家处理后才清除 `pending` 并回到准备态。
- `settleEmptyCast(save)` 输入当前存档，输出 `processCatch` 结果或 `null`；仅当当前竿无钓获且状态为 `cast`/`result` 时生效。它复用 `finishCast` 和 `processCatch('study')` 的记账语义，不额外奖励空钩。
- 若恢复的空结果已经标记 `processed`，仅清理 `pending` 并返回 `alreadyProcessed` 标记，不再次记竿、扣竿或发奖励。
- 旧版未决抛竿若已无钓获且超过 `readyAt`，必须进入空钩，即使它没有旧策略记录；不得永久停在观察鱼口。

### 失手后的鱼讯追踪

- 新存档可含 `waterTrail:null | {fishId,spot,bait,reason}`。自然鱼口超时或搏鱼脱钩时，先在本竿 `pending.nearMiss` 保存已接触到的活体鱼种，再将 `catch` 清空；空钩结算时才形成一条可追的鱼讯。沉水物、从未接触鱼的空钩和旧存档中缺失鱼种的空钩不生成鱼讯。
- 鱼讯只作用于**下一次确认抛竿**。同钓点、同鱼饵且该鱼仍在当前可钓池时，目标鱼种有 62% 的回游抽取机会，等待缩短 1.4 秒；若回游成功，提竿窗口额外增加 2 秒。一次抛竿无论是否沿用原钓点/鱼饵，都会消耗旧鱼讯；再次失手可以形成新的鱼讯。稀有鱼仍受天气、线索和装备门槛约束，不能由鱼讯保证出现。
- 当前轮次不再缩短新抛竿的提竿窗口，各轮基础窗口均为 9.5 秒。已创建抛竿保留存档里的 `biteWindowMs` 与 `readyAt`，不因规则变更重抽。
- 准备态用水边提示告诉玩家“同钓点、同鱼饵再抛可能追到刚才的鱼影”；确认抛竿后若同类鱼真的回游，接近阶段的提示予以呼应。没有任何额外限时按钮或选择题。鱼讯不直接发奖励或调查进度。
- `migrateSave` 对旧存档缺失或畸形的 `waterTrail` 归一为 `null`；消费和空钩结算须保持幂等，刷新不得重复产生或消耗追踪机会。

### 钓获处理的轻重节奏

- `src/catch-presentation.mjs` 的 `catchActionPlan(save, catch, fish, sameCount)` 只输出结果页的建议操作和 notable 身份标识，不改变 `processCatch` 的奖励或容量规则；notable 不再触发默认展开。
- 所有钓获先展示一个可直接点按的建议操作；“其他选择”可展开其余三个操作，不自动替玩家决定。首次记录、特殊/变异和追踪身份由标签强调，仍默认收起替代动作；鱼种说明和搏鱼明细由独立 details 展开。小屏展开其他选择时折叠鱼体展示、保留鱼名与属性；具体布局见 `coastal-ui-spec.md`。
- 建议操作优先服务尚未完成的本轮目标。活体放流目标不能推荐放流沉水物；收藏位已满时不能推荐收藏。目标已完成或建议不可行时推荐做成记录。其他操作仍可选，容量不足由 `processCatch` 返回可见错误，结果页保持打开。
- 刷新恢复同一次钓获时按存档重建建议与展开状态；展开/收起只是界面状态，不改变存档、钓获或轮次。

旧存档若停在未完成的三选一读漂，应转入新的自然咬口阶段并保留原有钓获；已完成旧选择的抛竿沿旧结果结算。错过提竿窗口时不猜测任何策略，也不发放原三选一的连段奖励。鱼口消失、浮漂回稳，钓获转为空钩；重复超时不得再次处理。

## 近景瞄准与确认

- 准备态点按“选落点”进入瞄准态：从当前视角平顺切到近景，显示当前钓点的默认落点预览；不得创建 `pending`、扣除本轮竿数或抽取结果。
- 瞄准中可随时切换俯瞰/近景，已选落点不变；俯瞰确认立即开始抛投并保持俯瞰，近景确认才等待镜头就位。
- 瞄准态点按任意可见水面选择落点；射线命中可达圈外的水面时，沿当前钓点至触点方向收束到可达水域边缘。按住水面拖动时持续按触点射线更新，光圈沿手指方向移动；松手不再次投射射线，以免标记跳动。岸上触点和无法形成水面射线的触点保持上一个有效落点。
- 可抛范围由当前钓点中心、最大距离及岸线共同决定，场景以同一计算结果绘制范围；点击范围外的水面时，光圈应沿触点方向停在范围边缘。范围不是额外可选按钮，也不改变现有三钓点的解锁规则。
- 近景准备态即显示当前钓点的可抛范围，进入瞄准后沿用同一范围；只有落点光圈的意义从默认位置变为玩家的当前预览。切到俯瞰时可看到三个钓点的范围，切回近景不丢失当前范围。
- 近景准备态轻点当前范围内的水面，在松手时进入瞄准并把触点设为预览落点；单指拖过短距离后进入瞄准并连续调整，松手只停在预览，不直接抛投或扣次数。第二根手指加入时放弃候选选点，继续原有双指缩放。范围外点按仍是普通水面观察，范围外拖动保留巡看镜头；俯瞰点按仍优先选择钓点。按钮“选落点”保留为可靠入口。
- 瞄准态点按固定“抛竿”按钮才调用 `makeCast`；按钮不承担拖动选点，单次触摸不能同时进入选点并确认。确认时以当前有效预览落点创建抛竿。
- 若确认发生在镜头进入瞄准的过渡中，先锁定本次有效落点并等待镜头就位，再调用一次 `makeCast`；等待中再次确认不重复抛投，取消则撤销排队确认。
- 水面拖动从当前触点更新预览，触摸松开或取消均不触发抛竿。底部按钮上的触点抖动不得更改落点。
- 瞄准态提供触控可及的“取消”，返回准备态且不改变存档。键盘确认可作为桌面兼容路径，不是移动端必需条件。
- 有效触点出现短促的水纹与落点扩散环，确认进入瞄准、点按或拖动选点都能感知落点变化；持续拖动时控制反馈频率，不能每个指针事件都创建一组水纹。
- 近水/远水的鱼情与提竿宽容度可以在准备态的下一步引导中说明；瞄准时仍以水域光圈与落点预览为主，保持“在亮起的水域点选，拖动调整”。具体难度与水域解锁规则见 `docs/design/progression-guidance-spec.md`。
- 切换钓点时重置预览；已有 `pending` 或无法抛竿时不进入瞄准。刷新后未确认的瞄准不持久化，已确认的抛竿仍按原有存档规则恢复。

## 边界与异常

- 刷新或重复处理同一次钓获，不应重新抽取鱼种或重复发放奖励。
- 旧存档缺失新字段时应迁移，已获得的进度不得丢失。
- 本地存储不可用时，界面应给可见提示；不得静默宣称持久化成功。
- 没有鱼或读漂失误时应进入空钩/失败路径；稀有个体不得由线索直接保证出现。
