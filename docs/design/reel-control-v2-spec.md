# 核心垂钓竿柄 V4：四向设计与接入规划（历史草案）

本版的微型钓具触点已被玩家否定。现行规格见 `docs/design/fishing-control-v6-spec.md`，不再沿用本版54×88px触点设计。

状态：交互设计草案，尚未接入运行游戏。日期：2026-10-01。
依据：HANDOFF、fight-simulation-spec、coastal-ui-spec、现行reel-gesture与玩家反馈。

2026-10-01运行接入修订：本文件的旧线轮/端点视觉与180ms回中设计已由 `fishing-control-v7-spec.md` 替代。活动入口为暖杏连续曲面与钓钩浮雕，124px固定输入、420ms有限展示回弹；真实手势/引擎接口延续，浏览器与真机待验。

## 1. 目标与被否定的表达

同一入口承担按住提竿/收线、上划抬竿、下划让线、横移调竿、松手卸力。让玩家从接触面、移动路径和动作响应读懂输入；视线主要看水面和竿线。没有新的绕圈或节奏点击玩法。

机械圆盘、同心圈、轴心/摇柄、悬空提示卡、文字方按钮、常驻正常状态条均被否定。第三版虽然有横向输入，纵向滑槽仍误导为只有上下，普通拇指块也缺少钓具识别；第四版替代它，不修改原手势规则。

## 2. 布局与视觉职责

- 原112×112px命中区与中心保留：无safe-area时right32px/bottom52px。原连续指针捕获保留，底座和事件节点永不跟手移动。9:16竖屏优先；横屏仅兼容。
- 触点为简化钓竿握持部：短竿段、海盐绿线轮座、暖软木握把，54×88px轮廓；软圆角与薄侧面表达体积，无内部齿轮、同心圈、摇柄、插图或贴图。线轮座是静态钓具结构，不根据按住做假旋转。
- 去掉纵向槽，根部只有局部接触阴影和短连接段；四边有同级轻方向标记，左右不能弱于上下。标记不做四颗可点按钮；按住后方向对应实际输入亮起，松手淡回。常态无文字、仪表或大底板。
- 按住握把下沉2px并减小接触阴影；dx/dy以0.65映射到32px半径圆内，横纵范围完全相同，斜向连续移动。竿柄随横向输入做最多±12°有界倾斜，命中区与根部不移动。松手180ms回中；手势阈值保持现行值，视觉不自行触发动作。
- 普通上端点低对比；只有真实pumpOpportunity可用时上端点变暖并上移提示一次（240ms）。触点到上端且动作被接受时端点变为短确认勾；拒绝不会亮成功状态。
- 下划进入让线后下端点实亮；回中恢复连续握持。横移点亮对应左/右标记并侧倾，不能误触抬竿或让线。斜向按真实偏移点亮对应两侧，但机会色/成功勾仍仅由真实可用性/accepted决定。危险不因回中或松手清除。
- 临界风险仅让底座两侧收紧标记呈珊瑚色；使用短句“松手”作为必要的瞬时补充，已松手/正在让线时收起该命令。松线不抖动、不警报。不展示正常状态句，也不重建受力仪表。
- 样例外“播放手势”仅为观察设计运动，不属于产品按钮。常态无字的可发现性、首次一次图示教学需要新玩家试玩，不能在未验证前宣称教学有效。
- 原左上搏鱼摘要与场景继续解释鱼种、距离、竿弯、线张力。样例用真实3D静态截图做构图背景并隐藏旧摘要，避免演示状态和静态数据矛盾；入口本身为可操作DOM。

## 3. 输入、状态与提示优先级

手势不变：上划超过42px、横向≤30px且机会允许；下划≥24px进入让线；抬竿回到起点上方12px以内、让线回到起点下方10px以内恢复收线。一机会不能连续抬竿。横划保持原调竿输入，不能误触上/下。

| 状态 | 图形反馈 | 必要文字 |
| --- | --- | --- |
| 常态/按住 | 钓具中位/握紧下沉，四向同级可读 | 无 |
| 咬稳提竿 | 按住后确认勾一次，继续同指针收线 | 无 |
| 抬竿机会 | 上端点实亮，一次短上移 | 无 |
| 有效上划 | 竿柄上移，上端确认勾 | 无 |
| 无效上划 | 不出现确认勾，单次纠错 | 先收紧 / 先稳住 |
| 下划让线 | 柄下移，下端点实亮 | 无 |
| 回中 | 柄回到根部，继续下沉收线 | 无 |
| 横移 | 左/右标记分别点亮，竿柄侧移与倾斜；不触发上下动作 | 无 |
| 临界且仍硬收 | 侧面收紧标记，危险不被普通确认覆盖 | 松手 |
| 已松手/已让线但风险未退 | 收紧标记保留，取消重复命令 | 无 |
| 收回挂物 | 同入口点按，短确认勾，不进入搏鱼 | 无 |

优先级：终态 > 临界风险 > 正在让线/抬竿 > 短纠错 > 可用机会 > 常态。短反馈只在事件变化时触发一次；没有真实accepted不得给成功勾或音画振动。

## 4. 数据结构与接口

计划继续用纯展示决策扩展reel-control-feedback，不写存档、不改物理。输入mode、有效fight、held/paying、gesture当前dx/dy、pumpOpportunity、真实accepted/rejected事件的key/过期时间、单调时间；缺失或NaN回退中位/无机会/无风险，不重播恢复事件。

输出建议：`{inputMode, gripOffset, aimDirection, gripTilt, pressedDepth, guide, riskTone, resultKind, correction, ariaLabel, eventKey}`。

- inputMode为idle/hold/lift/payout/side；gripOffset有限且有界，与命中节点分离。
- aimDirection为none/up/down/left/right及四个斜向；低于8px实际偏移为none，8px仅用于视觉防抖，不改连续调竿输入。判定基于原始dx/dy，不能从夹限后的角度判断手势；侧向表达超过12px时显示side，与原30px竖向手势容差分开。
- guide只说明可用方向/回中，不根据视觉位置判定动作成功。风险复用原过载判断，拒绝原因取原pumpRod结果。
- ariaLabel保留操作/状态说明供读屏；常态文案不渲染到视觉层。离散结果用aria-live，不逐帧播报坐标。
- 第二指针不能接管；pointercancel/lostcapture/blur/页面隐藏/换鱼取消旧输入、动画和短事件。

## 5. 动效、边界与性能

跟手期间不使用补间延迟；按下90ms下沉，释放180ms回中。方向机会与成功为单次动作，不开永久动画循环。减少动态时取消回弹/端点动作，坐标、动作和风险立即更新。

正式接入只复用DOM/CSS和现有音画触觉事件，不新增3D对象、draw call、shader或纹理。低端手机需量测帧时间和指针延迟。所有标记和短提示pointer-events:none，不吞掉水面输入。

样例播放手势为一次计时序列，与实际样例事件共用begin/move/end；手动按下、换状态、失焦会取消播放。不触发游戏物理/存档/声音/振动，不能证明真实手感。

## 6. 接入顺序与验收

P0先统一临界风险与短确认的决策，再保留原事件节点接入触控柄；端点与结果绑定真实可用性和accepted；最后完整真机验证按住→收线→松手→上下划/回中→左右调竿。不能只凭静态图或演示动画登记运行完成。

测试：四个主方向和斜向表达、等半径有界位移、原竖向门槛和拒绝、防连触发、回中、第二指针/cancel/失焦/换状态、演示接管、缺失值/无假成功。验证不使用Computer Use，采用实际样例脚本的事件与几何检查；本轮不声称浏览器实画、safe-area、新玩家发现性、真机手感或低端设备通过。
