# 场景、水面与镜头规格

> 状态：源码与运行资源已恢复，构建和相关自动测试通过；真实浏览器/设备画面仍待验收。

## 目标与范围

使用 Three.js WebGL 场景呈现暖海岸、可读的水面、角色与鱼。巡看、瞄准、等待、搏鱼和收获采用各自构图；水面反馈与浮漂、鱼和手势的位置一致。美术目标及待解决问题详见 `HANDOFF.md`，它是历史交接材料，不等于当前功能验收记录。

## 数据与依赖

- 渲染模块为 `src/scene.js`、`src/water.js`、`src/fishing-motion.js`，运行资源位于 `public/assets/`。
- `assets_pipeline/` 保存 Blender 源文件、部分导出预览、清单和生成脚本；不能将源资产存在等同于运行时加载成功。
- 水面包含低频波、双法线贴图、深度折射、吸收/散射、反射、岸边接触与局部涟漪。画面参数集中在 `src/render-settings.js` 与 `src/render-defaults.js`；物理岸线由 `src/coast.js` 提供。

## 接口与输入输出

场景输入为相机状态、抛竿落点、鱼/浮漂/钓线状态、天气与玩家水面手势；输出为帧画面、镜头转换、鱼影和局部水面扰动。现有测试要求镜头过渡连续、鱼体方向正确、水流手势采样不依赖事件批次，并要求视觉资源的路径可用。

开场镜头分为远景接近、绕角色约 120 度、回到正常巡看视角三段；段边界位置与目标点连续，结束时位置、目标点和视角精确等于正常镜头。两艘远景渡船应在桌面和竖屏的默认侧后方镜头中保持可见。

岸边水体抬升使用当前移动接触线对应的地形高度。接触线移至水下沙地时，水高须匹配海床函数；移至干沙时须匹配近岸地形。渲染着色器仍需把被水覆盖的沙地压到水面以下，避免穿出薄水层。

## 边界与异常

- 手机竖屏和桌面居中竖向画幅都要保持落点、浮漂和玩家可见。
- 地形、水面、反射和远景不能在可操作镜头下露出明显边界。
- 不可用贴图或模型应被构建校验发现；运行时降级行为仍需按场景逐项验证。
- 渲染、美术资源和真实设备性能主要靠截图、录屏及设备测试；纯计算部分仍应单元测试。

## 验证要点

运行 `tests/water-flow.test.mjs`、`tests/water-shading.test.mjs`、`tests/fishing-camera.test.mjs`、`tests/camera-intro.test.mjs`、`tests/coastal-art.test.mjs`。然后按 `HANDOFF.md` 的截图清单检查准备、瞄准、等待、咬口、上鱼与旋转镜头。静态源码断言不能替代真实渲染验收。
