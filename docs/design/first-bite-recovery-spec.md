# 首竿鱼口失手后的下一竿提醒

日期：2026-10-02。状态：P0 实施规格，补充 `docs/design/opening-cast-spec.md` 与 `docs/design/next-cast-slice-spec.md`。

## 目标

玩家首竿确实等到活鱼咬实、却未在窗口内提竿时，下一竿准备态把失手原因转成一个可执行的小动作：看见鱼线绷紧便按住右下钓钩。继续保留同点同饵的非必中鱼讯，不给假奖励、强制教学窗或自动提竿。若失手发生在搏鱼中，不猜测是提竿太慢。

## 数据结构与接口

- `firstBiteRecovery(save)` 是无 DOM 的纯函数，输出 `{cue,detail}` 或 `null`。只读现有 `casts`、`trip.number`、`trip.moments` 和 `pending`；不新增存档字段。仅 `casts===1`、第一轮、无未决抛竿且首竿 moment 为有效活鱼 `near-miss`、`missReason==='missed'` 时返回提醒。
- `cue` 用于准备态的短动作指引；`detail` 用于下一竿鱼讯详情。有效 `waterTrail` 仍由原有水域、鱼饵、天气和权重条件决定；提醒本身不改变 `waterTrail`、鱼池、等待时间或提竿窗口。
- `actionCuePresentation` 接收可缺省的 `firstBiteRecovery` 结果，准备态在选点提示处显示短提醒。瞄准、等待、咬实、搏鱼、处理和结果态不显示。刚换饵/钓点的操作确认仍优先显示，过期后恢复提醒。
- `nextCastThread` 的失手鱼讯仅在该提醒存在时用 `detail` 解释上一竿的提竿时机；继续方向仍是当前合法的选点、换饵或瞄准动作，不保证同一尾鱼回来。

## 边界与异常

- 首竿无鱼、挂物、已提竿后搏鱼游脱、旧存档缺少结构化 moment、损坏鱼种/时间/原因均不显示提醒。第二竿一旦确认抛竿，`casts` 增加之前可能仍为 1；因此 `pending` 存在时也必须隐藏。第二竿结算后自然停止。
- 玩家可自由换点、换饵、关声音或直接离开；提醒不阻止任何选择。刷新后从已保存的事实重建；页面隐藏时不额外发声或振动。
- 复用现有文字提示，不新增模型、贴图、shader、draw call 和定时器。9:16 的 390×844 与 320×568 检查短文案可读、按钮仍可触达；低端真机触控及真实玩家理解度另验。

## 验证

Node `node:test` 覆盖真实首竿超时、第二竿开始与结束、搏鱼失手、沉水物/空钩、旧及损坏存档、UI 模式优先级、鱼讯资格和非必中文案；浏览器核对首竿失手后的准备态及下一竿等待/咬实画面。
