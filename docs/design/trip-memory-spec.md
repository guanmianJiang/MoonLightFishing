# 真实行程回顾与下一竿入口规格

日期：2026-10-02。状态：P0 实施合同，承接 `docs/design/long-term-play-spec.md` 的一次小行程目标。

## 目标

收竿页只回顾本轮真正发生的一件值得记住的事，并提供一个可执行、非必中承诺的继续方向。玩家看过鱼影、轻提或失手后，不再因最终空钩被笼统写成“水面安静”；未完成轮次目标不在收竿页当作失败任务展示。四竿仍是可继续的轻量分段，不是体力限制。

## 数据结构与接口

- 当前 `trip` 增加可缺省的 `moments` 数组，每次合法 `processCatch` 最多写入一条，最多保留本轮四竿。单条 `{castId,kind,fishId?,action?,discovery?,returned?,mutation?,missReason?}`。`kind` 仅为 `landed`、`object`、`near-miss`、`quiet`；鱼种和“重逢”只来自当前真实 `catch` 或 `nearMiss`，发现状态只来自本竿有效 `discoveryTransition`。不保存 UI 文案或逐帧过程。
- `makeTripMoment(save,pending,action)` 是无 DOM 的纯函数；若缺少稳定本竿 ID 或数据损坏则返回 `null`。引擎在处理方式成功且结算一次时追加；容量/动作错误、重复处理、刷新恢复不得重复追加。`startNextTrip` 清空本轮 moments，旧 v1/v2 存档缺少字段时迁为空数组，保留已有 `changes` 和未决抛竿。
- `tripStory(trip,thread)` 只读取本轮结构化 moments 和有效 `nextCastThread`，输出 `{lead,notes,continueLabel,hasNextAction}`。回顾优先级：已支持的观察、待验证的观察、真实重逢、特殊钓获、普通钓获、沉水物、有身份的失手、仅看见、安静。相同层选较近的一竿。最多一个回忆卡和一个下一步卡；无有效方向则只给自由返回水边，不编造线索。
- 玩家主动选择的水情问题若实际钓到对应活体，可作为回顾候选，排在已支持的观察/待验证的观察之后、普通钓获之前；失手、挂物或未经验证的问题不得被写成已确认规律。字段与文案边界见 `docs/design/water-question-spec.md`。
- 旧行程如果只有历史 `changes`，仅从明确的处理文本给概括回顾；不能反推鱼影、个体身份、发现或失败原因。损坏 moment 或未知鱼种安全忽略。

## 玩家流程与交互

1. 结果处理成功或空钩自动结算时记录本竿事实；发现、失手、钓获、放流均可作为事实来源，互不因选择处理方式而覆盖。
2. 本轮结束后，画面先表达最重要的一件事，再显示“下次可试”与一个具体动作。方向沿用现有鱼讯、观察、新水域、追踪优先级，并由真实当前水情重新检查；不提供必中、保底、额外点数或倒计时。
3. 点按主按钮先开启下一轮，再执行当前仍有效的路线动作：换钓点、换饵，或进入近景瞄准。进入瞄准后仍必须由玩家单独确认抛竿。若水情在收竿页期间变化使方向失效，只回到准备态。
4. 关闭收竿页视为“先收工”；不扣竿、不改变未完成观察。下次回到游戏时仍可继续，手记保留证据。

## 边界与验证

- 空钩且无真实事件时允许安静，不奖励“等待线索”。同种鱼讯不称为同一个体；仅有 `tagId` 的上岸活体可称重逢。沉水物不能写活体、搏鱼评级或放流记忆。
- 已识别的鱼口超时失手可提示下一次在咬实窗口按住提竿；搏鱼中游脱只描述真实失手，不猜测具体操作原因。
- 回顾不影响鱼池、天气、钓获/失手判定、经济和装备。界面仅复用现有文字卡，不新增纹理、模型、draw call 或 shader。
- Node `node:test` 覆盖各类真实 moment、优先级、4 竿边界、重复/错误处理、旧存档、空钩与未知 ID、下一轮清理及按钮动作。390×844、320×568 检查收竿卡与继续入口；低端真机触控与玩家第 4/8/20 竿继续意图仍需试玩。
