# 项目结构与配置规格

> 状态：2026-09-28 迁移整理已实施。依据旧仓库已跟踪的 `dist/` 恢复源码，自动测试与构建已核验。旧仓库仅是文件恢复来源；后续开发只在新仓库进行。

## 目标

将可编辑源码、运行时静态资产、美术生产资料、测试、构建工具和生成产物分清；让 Git 克隆后的项目能够安装依赖、运行测试和构建。减少散落在代码中的玩法数据、存档键、版本号和资源路径，同时保留现有存档及玩法行为。

## 目录职责

| 目录 | 内容 | Git 策略 |
| --- | --- | --- |
| `src/` | 可编辑的 H5 程序、UI、样式、着色器与运行时配置 | 跟踪 |
| `public/assets/` | 游戏运行时直接加载的模型、贴图、字体与音频 | 跟踪 |
| `assets_pipeline/` | Blender 工程、生成源文件、预览和美术说明 | 跟踪；不作为运行时直接加载路径 |
| `tests/` | 对 `src/` 的纯逻辑、结构与构建验证 | 跟踪 |
| `tools/` | 资源生产、检查和维护脚本 | 跟踪 |
| `docs/` | 模块规格、总清单及一致性记录 | 跟踪 |
| `archive/legacy/` | 不再作为入口的历史页面、样式和旧控制器，供追溯 | 跟踪；构建和测试不引用 |
| `build/` | Vite 构建产物 | 忽略，重新生成 |

恢复时只读取旧仓库 Git 跟踪的 `dist/` 内容，不复制 `dist/dist/` 或 `dist/_backup/`。初步保持模块间相对导入路径和存档格式，先使测试与构建恢复，再逐步拆分大文件。活动页面入口为 `src/index.html` → `src/app-final.js` → `src/scene.js`；确认没有活动引用的旧入口移入 `archive/legacy/`，保留追溯材料。

## 配置与数据边界

- 玩法目录数据（钓点、鱼饵、鱼种、装备、目标、规则、鱼讯文案）应独立于结算逻辑，并保持已有导出接口兼容。
- 可调玩法参数（天气轮换、出行竿数、等待与读漂时长等）应集中配置，避免同一值在 UI、逻辑和测试中多处写死。配置模块只能含纯数据，不依赖 DOM、Three.js 或浏览器存储。
- 存档键和版本必须集中定义；迁移函数仍负责旧数据兼容。调参不应改变已保存的 `pending` 抛竿结果。
- 资源路径由一个静态资产清单或可预测的统一前缀管理；构建校验应检查清单中的发布资源。

## 接口、输入与输出

- `npm run dev`：从 `src/index.html` 启动本地开发。
- Windows 用户可双击仓库根目录的 `启动游戏.cmd`；入口在仓库根目录启动 Vite，等服务就绪后用默认浏览器打开实际端口，并在命令窗口关闭时结束服务。未安装依赖时先安装；缺少 Node/npm 或服务启动失败时在窗口中给出可读错误。
- 直接以 `file://` 打开 `src/index.html` 时，页面应明确提示需要本地服务及 `启动游戏.cmd`，不能留下看似可操作的空场景；通过 HTTP(S) 打开时提示保持隐藏。
- `npm test`：运行 Node 业务测试及必要的结构检查。技术栈已确认使用 Node `node:test`，不使用 Unity。
- `npm run build`：生成 `build/`，包括程序包和 `public/assets/` 运行资源；校验入口、关键资源和包文件。
- 存档输入仍来自 `moonwater-v1`；输出数据结构需保持迁移与幂等结算规则。

## 边界与异常

- 源码或资源不完整时构建必须失败；不能引用旧构建副本掩盖缺失。
- 开发依赖应保持可安装并通过当前 npm 安全审计；升级后须重跑全部测试与构建。
- 文件移动不能改变已有相对 URL、游戏机制、存档键或资源归属。若不可避免，先增加可执行回归测试。
- 重复资源与旧入口必须经依赖图及测试确认后才能移出活动目录；先保留可恢复记录。
- 大型美术文件无需纯业务单元测试，但须做存在性/构建校验及视觉检查。
