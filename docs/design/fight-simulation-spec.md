# 搏鱼与钓线规格

> 状态：源码已恢复，纯逻辑测试已运行；视觉表现仍待验收。依据 `src/reference-loop.mjs`、`src/fishing-motion.js` 及配套测试维护。

## 目标与范围

鱼距、出线长度、线张力与竿弯共同驱动搏鱼反馈。玩家收线、放线和抬竿应有不同效果；鱼的游动、转向、潜水和出水应与同一状态一致。

本轮把“认鱼、读动作、做决定、复盘”做成核心循环。鱼种不能只是体重不同：玩家应从蓄力时长、冲刺次数、贴底停顿和回气窗口识别习性，按鱼种改变松线与抬竿时机。结果保留每种鱼的最佳搏鱼表现，鼓励在同一水域反复挑战手法；不额外引入货币奖励。

## 数据结构与接口

- `src/reference-loop.mjs` 的 `createFight`、`stepFight`、`pumpOpportunity`、`pumpRod` 维护搏鱼状态，至少暴露 `status`、`tension`、`fishPosition`、`lineLength`、`reelTurns`、`spoolVelocity`。
- `createFight({weight})` 初始化搏鱼状态；`stepFight(state, reeling, dt)` 随时间推进并改变状态。测试预期状态可达 `won` 或 `lost`。
- `src/fish-behavior.mjs` 以稳定鱼种 ID 返回只读行为档案：`name`、`habit`、`tell`、`counter`、`windup`、`run`、`recover`、`thrust`、`reelFactor`、`lateral`、`chainEvery` 等。未知 ID 回退为标准型，旧存档进行中的搏鱼无需迁移字段。
- 搏鱼状态增加 `behaviorId`、`cleanRuns`、`goodPumps`、`runsSeen`。`fightReport(state)` 返回可存入单次钓获的 `{grade, cleanRuns, runsSeen, goodPumps, seconds}`，只在真正钓上时写入 `catch.fightReport`；同种鱼的最佳成绩持久化到 `fightRecords`，旧存档缺少该字段时初始化为空。`migrateFightRecords` 过滤未知鱼种和异常值。
- 钓线几何由竿尖、浮漂/鱼位置、松线和受力决定，主要位于 `src/fishing-motion.js`；飞行与阶段动作也由它和 `src/cast-flight.mjs` 协作。
- 鱼的朝向、鱼嘴和钩点关系由 `tests/fight-fish-motion.test.mjs`、`tests/fish-attachment.test.mjs` 约束。

## 输入输出与规则

输入包括鱼体重、帧间隔、收线/放线/抬竿动作及鱼的自主运动；输出包括鱼距、出线、张力、疲劳、动画姿态与胜负。固定物理步长应使不同显示帧率得到接近的结果。绷紧的线应传递负载，松线应下垂；冲刺时放线可降低过载风险，合适时机抬竿应产生可测的拉近效果。

### 上钩后的第一段对抗

- 新搏鱼从约 2 秒的 `hookset` 调整期开始：鱼先在落点附近摆动并逐渐带紧鱼线，再进入本鱼种的蓄力和冲刺。调整期的基础外游力较弱，给触屏玩家时间辨认收线与松手；不暂停物理、不锁住鱼距，持续放任仍会失鱼。
- 调整期的文字只解释“先收紧线，观察竿弯”，不能提前宣称鱼在冲刺或推荐抬竿。`pumpOpportunity` 不将此期标为好机会；阶段结束后保留各鱼种原有的预兆、冲刺、回气、让线与抬竿策略。
- 移动端搏鱼只展示一个收线操作区：按住收线、松手让线；按住时若鱼放缓且 `pumpOpportunity(f,false).ready`，从触点起始位置向上划超过 42 CSS 像素，转为一次短促抬竿，期间暂停手动收线；手指向下滑回起始位置附近便继续收线，松手始终停止收线。下一次有效上划才可再次抬竿。调整期、冲刺、贴底、竿回落、松线过多和无效搏鱼状态中的上划不应意外中断原来的收线。单指 pointer capture 支持滑出按钮后返回；其他触点及失焦/取消不应让收线卡住。双指和鼠标兼容路径不承担移动端必要操作。
- `src/reel-gesture.mjs` 只判断手势阶段、上划进度与 lift/reel 转换，不修改搏鱼物理；游戏层收到 lift 后先暂停按住状态再调用 `pumpRod`。操作区在有效窗口显示上划提示和随触点上移的轻量箭头，抬竿时显示滑回收线；鱼发力时提示松手。无需第二个抬竿按钮。键盘上箭头保留为非移动端兼容入口。
- 抬竿是短促地把鱼拉近，竿回落后靠按住收线守住这段距离。`pumpRod` 仅在 `pumpOpportunity.ready` 时生效；冲刺、蓄力、鱼仍明显外游、松线、收线按住、调整期和回落期不得启动动作、消耗体力或增加抬竿计数。抬竿反馈须在鱼距实际变化后显示本次拉近米数，不预先宣称成功；没有净拉近时说明先收紧线或等待下次机会。
- 旧存档中进行到一半的搏鱼保持现有 `fishState` 和鱼距，不能重新进入调整期。轻鱼持续收线仍可钓获，重鱼一直硬收仍会断线；无操作最终仍会失鱼。低帧率和高帧率的结果应接近。

### 角色、竿与线的同源反馈

#### 上钩鱼体的受力姿态

- 鱼进入可见范围后使用与钓获一致的实体模型及材质，由真实水体深度控制显隐；不得用半透明纯色鱼体覆盖水底，让鱼看起来像投影或贴片。钓线与鱼饵仍保持独立可读。
- 试饵末段必须提前完成朝向鱼竿的转身，并让鱼嘴在咬实前连续靠近钩点；咬实帧不得更换鱼模型、重置缩放或瞬间把位置和俯仰改到新值。搏鱼第一帧沿用咬钩鱼体与姿态，再向物理目标平滑过渡；异步资源到达时不能在可见鱼体上突然换模型。
- 搏鱼鱼体的水平朝向以鱼距与横向位置的实际速度为准：收线向岸时头部朝岸，冲刺向外时朝外，横向闪躲时头部随闪躲方向转；近乎静止时才使用受竿牵引的侧身待机角。转向有有限角速度，避免速度过零时瞬间翻面。
- 试饵鱼的水平路径以距咬钩时刻的连续时间计算，不因“接近、观察、轻咬、咬实”状态名切换而重置偏移；观察结束时鱼嘴对钩系数连续收敛到轻咬起点。输入缺失时路径返回有限位置。鱼嘴在咬实之前完成对钩，进入搏鱼后保留同一模型并在短时间内将位置与运动状态衔接。
- 鱼嘴接近饵钩要沿空间斜线游入：高度由鱼嘴到钩的水平距离决定，远时保持较深、水平接近时同步缓升，最后半秒主要是前冲与咬合，不允许水平已停下后才竖直上浮。`fishMouthApproach` 输出世界空间口缘目标，鱼体旋转后再以真实 `MouthAnchor` 对齐该目标。
- 咬实但尚未提竿时也要立刻进入受力表现：鱼影从试饵姿态转为可辨的鱼体，鱼头沿钩点逐渐上扬并朝镜头露出侧身，鱼嘴始终与浮漂下方的饵钩三维重合。进入搏鱼时鱼体大小应连续，初始 `hookset` 承接咬钩俯仰并随时间衰减，接着转到张力驱动，不得首帧重新平躺或缩小。
- `fightFishMotion` 从同一搏鱼状态的松线、瞬时张力、平滑负载、抬竿、径向速度和横向速度输出鱼体朝向、俯仰、侧倾与尾摆。线绷紧时鱼嘴受竿牵引，鱼头明显上扬；抬竿时上扬更强，放线和松线时减弱；外冲时鱼仍朝外游，不能因表现角度倒游。
- 近景镜头从角色后方看水面，鱼若始终沿岸线法向正对镜头，鱼身会被压成极窄正面轮廓。搏鱼鱼体应保留朝岸/朝外的速度分量，同时有受控横向偏角，使侧身和尾摆可读。偏角不得把鱼变成横着滑行的贴图。
- 鱼体旋转后钩仍与鱼嘴三维重合，短子线从浮漂下端接到鱼嘴；鱼体近岸出水之前保持水下，动作不改变搏鱼胜负、鱼距或存档。视觉验证至少检查绷线、松线、冲刺和抬竿，不能只用静态咬钩截图判断完成。

#### 持竿 IK 与上钩连接

- 每帧用固定上臂、前臂长度求解两只手。主手是竿柄的世界锚点，辅助手在抛投蓄力、释放、等待和让线时握住竿柄另一握点；实际收线时可离开竿柄摇轮。手臂不可随动作拉长，目标不可达时收束手的位置，并让鱼竿跟随收束后的主手，不让竿柄留在原目标点。
- 竿轴由同一抛投/搏鱼角度决定，并随身体俯仰和侧倾一起变换到世界坐标；辅助手的握点必须落在实际渲染的竿轴上。肩、肘、手的顺序和肘部朝向在近远抛、收线与松线之间保持连续；动作力度仍与落点距离关联。
- 鱼未真正上钩前，鱼嘴逐步靠近浮漂下的饵钩；咬实瞬间鱼嘴与饵钩三维重合。搏鱼开始后，实体钩随鱼嘴移动，短子线连接浮漂下端与鱼嘴，不能用一段零长度线假装连接。出水展示继续以鱼嘴约束鱼体旋转，模型异步替换也不得让钩点落在鱼体中心。
- 搏鱼与出水时，**鱼饵可见模型也应随实体钩转到鱼嘴锚点**，浮漂下原饵与原短子线不再显示，保留浮漂到鱼嘴的子线。资产晚加载时按当前挂钩状态放置，不得在浮漂下重新冒出第二份鱼饵；离开搏鱼后恢复到浮漂局部钩点。鱼饵 `HookAnchor` 与实体钩、鱼嘴的世界位置误差小于 1 毫米。
- 搏鱼每帧先求鱼体的最终位置、朝向和真实嘴部世界坐标，再把浮漂的水平坐标放到嘴部正上方，随后更新主线与浮漂到嘴部的子线。浮漂不可继续跟鱼身中心，否则子线会从背部跨到嘴，看起来像背部挂钩。浮漂高度仍由水面张力状态决定。
- 这些改动仅改变画面中的手臂、竿、钩和子线几何，不修改搏鱼胜负、落点和存档。继续复用现有网格与线对象，避免新增移动端 draw call。

#### 本轮表现迭代：距离与挣扎脉冲

- 抛投使用落点到角色的水平距离生成归一化力度。近点保留小幅挥竿，远点增加蓄力、释放后的手臂/身体回弹和竿稍滞后；力度只改变表现，不改变玩家确认的落点或抽取结果。浮漂飞行时鱼线余量从释放瞬间的短暂绷紧过渡到飞行中部的自然放线，再在入水时收敛。近远抛的入水水花应有可辨但克制的差异。
- 搏鱼表现从同一帧的 `tension`、平滑负载 `load`、冲刺 `surge`、鱼横向速度和线松弛量提取挣扎脉冲。脉冲同步作用于浮漂下沉/侧摆、线中段短暂传播、竿稍弯曲和持竿手/身体承受拉力；松线时脉冲迅速衰减，不凭空拉动人物。只增加已有几何顶点变化，不新增绘制对象。
- 鱼体挣扎须有短促的横摆、潜浮与尾拍，强度随冲刺、横向速度与张力升高；调整期也有逐渐衰减的第一次挣扎。浮漂水平位置跟随同一鱼体运动，线/竿/手的冲击从同一脉冲取值，不能鱼在抖而钩点或线端停在原处。静水、松线时回到小幅游动，不持续高频抖动。
- 鱼线脉冲有端点约束与幅度上限，不得使线脱离竿尖或浮漂，也不得形成反向闭环。瞬时受力停止后应快速回稳；帧时间异常或状态缺字段时返回有限数。
- 表现接口为 `castFeedback(age,distance)`、`castLineProfile(progress,distance)` 和 `fightPerformance(fight)`；输入分别是释放后的秒数与落点距离、飞行进度与距离、现有搏鱼状态，输出为无存档副作用的动作通道。`FishingLine.update` 可接收 `impulse`，只用于已有线几何的微幅波形。
- 鱼饵挂在浮漂下方的短子线上。`BaitMotion.update(floatPosition,dt,load)` 根据浮漂的水平运动给子线一个有上限的惯性偏移；负载越高偏移越小。鱼饵模型、备用鱼饵和钩点使用同一偏移，子线几何在原有对象上更新；新抛竿重置偏移。无效时间或位置不得生成非有限数。

- `src/angler-feedback.mjs` 从抛竿释放时间、咬实时间与搏鱼状态计算短促的释放回弹、咬钩冲击和受力/放线动作通道。输入时间可来自恢复中的存档；负时间、非有限数和过长间隔返回中性姿势。输出只改变画面，不改变胜负与数值奖励。
- 抛竿在竿尖释放线的瞬间先前摆，随后出现一次衰减的反向竿稍回弹；鱼口咬实后竿稍和持竿手先被带动，身体再小幅承受拉力。收线时双手、肩肘与身体持续受力；松手放线时握竿手向鱼方向让出、身体卸力，卷线手停止摇轮；抬竿只在实际 `pumpPulse` 中明显抬起。
- 线形始终连接当前竿尖与浮漂或鱼口锚点。`FishingLine` 将“松线下垂 → 受力拉直”在短暂时间内连续过渡，不能在单帧内把中间节点硬改成一条直线；高负载时仍必须迅速接近直线，避免画面与张力状态脱节。线段长度、下垂、竿弯和角色卸力应由同一搏鱼状态决定。
- 空线开始收回时，线轮对鱼线产生牵引，线长应从失手瞬间的余线迅速收向竿尖与浮漂间距；回收期节点向浅弧线收敛，不得在浮漂旁形成闭环或反向折线。未开始收回前仍可保留自然松线。
- 已钓获的鱼从搏鱼进入出水演出时，持竿姿势从最后的受力角度短暂过渡到举竿姿势；失手收空线不重演重鱼拉扯。所有新增动作保持 9:16 构图中的浮漂与鱼线可读，移动端不新增高面数骨骼、后处理通道或独立 draw call。

| 鱼 | 可观察习性 | 有效应对 |
| --- | --- | --- |
| 银背鲫 | 规律蓄力、冲刺、回气 | 预判冲刺松线，回气抬竿 |
| 细鳞白条 / 青壳河虾 | 短促、轻负荷 | 趁短回气持续收线 |
| 红鳍鲈 | 短预兆，可能连续二次冲刺，横向摆动更快 | 第一次冲刺后别急着抬竿，确认回气再带鱼 |
| 岩底鲶 | 长蓄力、贴底停顿，回气时机较长 | 先让线化解重冲，停顿结束后抬竿 |
| 断尾金鲤 / 银月鱼 | 连续或强力冲刺，回气窗口各异 | 先识别动作再改变收放线节奏 |

行为变化必须在物理状态、水面运动、振动/声音和简短触控提示中同源体现；不能只在说明文字里不同。成功让线以本次冲刺期间松手且保持线未大幅松弛为准；有效抬竿以回气窗口和质量阈值为准。表现评级只反映操作，不提高钓获权重或装备数值。

## 边界与异常

- 过载不能持续无限收线；持续无操作也应有失败终点。
- 抬竿不能无条件获得收益；需要合适窗口。
- 钓获近岸前应保持入水状态，出水动作与钩点相连。
- 对零长度、极小或大帧间隔等输入的数值稳定性，继续按后续修改逐项确认并补测。
- 未知鱼种、旧存档中的进行中搏鱼沿用标准型；旧日志没有搏鱼报告时不显示技巧纪录，不伪造最佳成绩。非鱼类钓获可显示过程报告，但不进入鱼种技巧纪录。
- 任何连续冲刺都必须有可见的第二次蓄力预兆；单区收线控件不能在冲刺或贴底停顿时标示上划机会。

## 验证要点

现有 `tests/reference-loop.test.mjs` 涵盖收放线、胜负、固定步长与抬竿；`tests/fishing-line.test.mjs`、`tests/fight-rig.test.mjs`、`tests/fight-fish-motion.test.mjs`、`tests/landing-motion.test.mjs` 覆盖线形、反馈和鱼体运动。视觉质量仍需录屏/截图核验。
本轮另测鱼种 ID 回退、不同鱼的冲刺节奏与负载、连续冲刺提示、有效应对计数、评级边界与最佳成绩；9:16 竖屏已核对游戏可启动，完整搏鱼画面仍待实机试玩。
