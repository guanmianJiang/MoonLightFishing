# 核心垂钓操作键 V5：接触面与四向反馈

历史草案：玩家已否定滑动时双块分离和外置箭头。现行规格为 `docs/design/fishing-control-v6-spec.md`。

状态：设计草案，尚未接入运行游戏。日期：2026-10-01。
依据：HANDOFF、fight-simulation-spec、coastal-ui-spec、现行 reel-gesture 与玩家反馈。

## 1. 目标

同一入口承担按住提竿/收线、上划抬竿、下划让线、横移调竿和松手卸力。操作仍然轻，主要视线留给水面、浮漂和竿线。第五版替代第四版：第四版把完整按钮缩成54×88的微型钓具，接触面不足、分量不够。明确取消这件小钓具；钓鱼识别由已有钓竿图标承担，按钮提供扎实接触面和真实动作反馈。

此前机械盘、同心圈、虚构摇柄、装饰插图、大字指令卡、常态状态仪表、竖向槽均不采用。主键只保留一个动作名，不重复“按住/正在/鱼线稳定”；没有新增绕圈或节奏玩法。

## 2. 视觉与布局

- 9:16手机画面优先。右下操作区148×148px，right20px、bottom28px；正式接入时另读取safe-area。可点事件节点是居中124×124px接触区，四向提示不扩大命中区、不吞水面输入。事件节点和底座固定，捕获后手指可滑出接触区。
- 主键面120×108px，位于区内left14/top16，显著大于第四版握把；顶部宽软圆角、下部圆角稍收，呈完整圆角厚键。杏色哑光面、浅暖高光、窄薄的低饱和绿侧沿和接触阴影构成体积；不做金边、玻璃、强光、粗描边或大托盘。
- 使用游戏已有cast钓竿图标作为静态图形资产；不另画微型立体钓具，不做假线轮旋转。中央图标42×42px，下面单行15px动作名。常态“收线”，咬稳“提竿”，挂物“收回”；真实让线/抬竿被接受后改为对应动作名。拒绝不显示成功动作。
- 按下键面下沉5px，侧沿从8px缩至3px，接触阴影缩短。拖动键面最大14px圆形等半径位移（实际dx/dy乘0.3）；四向和斜向连续跟手。图标最多±8°侧倾，键面本身不扭转。按住跟手无延迟；松手180ms回中。
- 四边同级方向标记，常态低对比；按住时增强，对应实际方向进一步实亮。上划机会只突出上标记，不能把所有方向染成机会色。临界风险以侧沿珊瑚色及一次短“松手”纠错补充，已松手/让线时收起命令；危险不会被成功确认覆盖。
- 有效提竿/抬竿/收回用一次小确认勾，不用星光、爆闪和大勾图。方向标记、底座、提示均pointer-events:none。按钮既是点击入口也是连续手势入口，不拆成四颗小按钮。
- 样例保留真实3D旧截图作构图背景；只演示操作区，不宣称当前场景渲染品质。外部状态选择与“播放四向”仅便于审阅，不属于产品流程。

## 3. 输入和输出

原物理手势门槛不变：上划dy<-42px、|dx|≤30且机会允许；下划dy≥24进入让线；抬竿回dy≥-12恢复握持；让线回dy≤10恢复握持。一机会不能反复抬竿。横移保持调竿，不绕过竖向容差。视觉方向死区8px；横向超过12px表达调竿，此值不替代物理容差。

输入：mode、fight、held/paying、原始dx/dy、pumpOpportunity、真实accepted/rejected事件、事件key与单调时间。输出：`{inputMode, gripOffset, aimDirection, symbolTilt, pressedDepth, actionLabel, guide, riskTone, resultKind, correction, ariaLabel, eventKey}`。有限值校验失败回到中位，不给假机会/假成功，不改物理或存档。

| 场景/输入 | 视觉反馈 | 动作名 |
| --- | --- | --- |
| 正常/按住 | 杏色厚键/键面下沉 | 收线 |
| 咬稳/有效按住 | 提竿进入同指针收线；短确认一次 | 提竿→收线 |
| 抬竿机会 | 只上端标记实亮，一次上移 | 收线 |
| 有效上划 | 键面上移、上端确认 | 抬竿 |
| 无效上划 | 保持收线，短纠错先收紧/先稳住 | 收线 |
| 下划/回中 | 键面下移/回中继续握持 | 让线/收线 |
| 左右/斜向 | 对应边标记亮，键面偏移、图标侧倾 | 调竿 |
| 临界硬收/卸力 | 风险侧沿保持；仅硬收出现松手 | 收线/让线 |
| 收回挂物 | 同入口点按，短确认一次 | 收回 |

优先级：终态 > 临界风险 > 已接受让线/抬竿 > 短纠错 > 可用机会 > 常态。危险覆盖成功勾和机会，但不假装替玩家执行让线。视觉动作名不产生引擎指令。

## 4. 边界和异常

只有原指针可以移动或结束手势；第二指针忽略。pointercancel、lostpointercapture、blur、页面隐藏、切状态清除旧输入、短事件和演示。取消后不得留下按压面或回放抢输入。确认650ms仅事件变化时触发。读屏保留完整操作说明和离散结果，视觉不输出完整状态段落。减少动态时取消回弹/机会动画，位移、反馈与风险立即更新。

## 5. 性能与验证

样例只用DOM/CSS与已有矢量图资产，单次7秒四向回放共用begin/move/end，结束或手动接管取消RAF；无网络、3D对象、shader、纹理载入或永动动画。正式接入需绑定引擎真实accepted、风险、声音/触觉，验证低端手机指针延迟和帧时间。

Node测试执行真实样例脚本，覆盖四向等半径、斜向连续、抬竿门槛/拒绝/防重复、让线回中、风险优先、动作名、第二指针/cancel/blur/隐藏、回放接管、异常值，以及288/320/390宽CSS几何边界。静态几何和事件测试不等于浏览器实画。遵守玩家要求，不使用Computer Use或桌面/浏览器自动化替代。

## 6. 本轮范围和接入

样例：`docs/design/prototypes/fishing-control-v5.html`。旧样例仅留历史。规格、沿海UI规格、总清单、验证报告同版；运行游戏未替换，不把草案登记为运行完成。

接入顺序：真实展示决策→保留现有指针节点接入键面→绑定机会/accepted/风险→真机按住、松手、四向、斜向、safe-area与竿线净空验收。按钮颜色/轮廓/真实按压感觉、拇指遮挡、新玩家发现性仍需视觉与真机验收。
