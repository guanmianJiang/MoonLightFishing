# 不同结果的音画情绪反馈

## 目标与边界

9:16 触控垂钓中，结果发生与钓获展示采用相应的镜头运动、实体声音、短旋律和环境混音。保持暖海岸休闲基调；不新增失败弹窗、长庆祝、闪白、滤色或额外奖励。反馈只消费已有结果，不改鱼距、随机、计账、窗口时长或存档。

## 分类与时序

| 结果 | 镜头 | 声音与情绪 |
| --- | --- | --- |
| 普通鱼 | 轻推、微抬、顺势停留 | 上岸实体声，展示时温暖短旋律，松一口气 |
| 首次记录 | 略多侧移，留出鱼体 | 明亮的发现旋律 |
| 重量纪录 | 慢推、较稳的托举 | 低音分量后上行，满足感 |
| 特殊来客 | 克制侧移与更近的停留 | 通透铃音与少量尾韵，惊喜 |
| 追踪重逢 | 柔和靠近 | 暖而熟悉的旋律，重逢 |
| 非鱼杂物 | 好奇侧移，不用活鱼托举强度 | 小水声、轻碰和两音问句，意外发现 |
| 空钩 | 小幅退镜，归于水面 | 轻收线声与水滴，平静 |
| 错过鱼口 / 脱钩 | 短暂停留，随后退出 | 短水声与下行音，遗憾但不惩罚 |
| 断线 | 保留现有极速回弹镜头，0.4 秒后才轻退 | 首帧短断裂/风声，短混音留白后回归海浪，突然失力 |

成功在 `arrival` 播实体声与轻落定；`reveal` 才播身份旋律。失败仅 `arrival` 一次，收空线结束不再叠第二段失败旋律。重复更新、恢复结果窗与静音恢复不重播；每竿每阶段最多一次。

活鱼出水的实体水声仍由场景 `onFishLift` 对齐实际提起帧，结果到达只补轻落定音，避免叠两次同样的水声。杂物独立进入跟随镜头，取景稍偏侧、视角略宽，不沿用活鱼的出水挣扎和托举特写。

## 数据与接口

角色面部同时读取真实鱼口、张力和结果阶段，表情时序与边界见 `angler-expression-spec.md`；沿用当前头部取景，不新增表情音效或特写镜头。

### 可感知性修正（2026-10-01，第二版）

第一版小幅运动在相机阻尼后不够明显，身份旋律只在结果窗打开时触发。第二版将旋律和对应展示镜头移到真实上岸过程：演出至少 1.05 秒且钩点高于 0.55 米时，场景发出 `onOutcomeShowcase`；应用按原去重器消费 `reveal`，结果窗随后打开不重播。恢复的 `result` 不触发场景展示事件。若提前条件未满足，结果窗保持原兜底触发。

- 增强推退和侧移的类别差异，视角变化控制在 4.5 度内，运动仍从零连续进入/退出；推退沿相机指向目标的水平视线计算，不能沿抛竿方向把“推近”做成远离钓获；保留断线前 0.4 秒回弹优先。
- 普通/首次/纪录/重逢旋律每音增至 0.065，特殊 0.08、杂物 0.05；失败实体声与扫频提高到可辨范围。环境声短时让位，不改声音开关偏好。
- `outcomeShowcaseReady(pending,revealing,age,mouthHeight)` 是无副作用的展示资格判定，排除无钓获、非演出、已结算、无效时间和仍在水下；每竿场景最多发一次。测试实际场景回调接线及应用“到达→上岸展示→结果窗”去重，不能只用手动音效预览判定完成。

- `outcomeKind({caught,fish,label,lossReason,reaction})`：无副作用分类；优先非鱼、追踪、特殊、首次、纪录、普通。失败优先真实原因，不将空钩误作断线。
- `createOutcomeDirector().emit(cast,stage,detail,at)`：输出 `{kind,stage,at}` 或 `null`；只保留当前竿的阶段集合，消费静音事件时也记为已处理，不写存档。
- `outcomeCameraCue(event,age,reduced)`：输出有界 `push/side/lift/fov/weight`；头尾归零，不累积偏移，断线避开前 0.4 秒物理回弹。减少动态效果时返回零。
- `outcomeAudioScore(kind,stage)`：输出有限长度的真实音效、铃音、扫频参数数组及 `duck/duration`。复用已有相对路径资源；通过 Web Audio 调度，环境声短暂让位且自动恢复。每个新结果阶段替换前一阶段剩余尾音；静音/后台取消已调度音源、恢复环境混音，HTML 音频回退的延迟片段以事件代次取消，恢复时不补播。

## 异常、性能与验证

选择钓获去向后的反馈见 `docs/design/catch-process-feedback-spec.md`。动作开始取消展示旋律的剩余尾音，放流入水声由实际水面交点触发；冷启动短音效的 HTML 回退从实际播放开始计时，并遵循 250 毫秒过期、静音、后台和结果替换取消规则。

### 实际播放与中断恢复（2026-10-01，第三版）

- 音频开关偏好与音频实际运行状态分别保存。只有输出图初始化成功且 `AudioContext.state === 'running'` 时才能显示“声 · 开”；中断后显示“声 · 待开启”，下一次触控重新调用恢复播放。显式关闭后任何自动恢复都不得打开声音。
- 初始化先建立音效主输出，再独立建立环境层；环境资源或可选混响失败不能阻断结果音效。主输出初始化失败要释放半成品上下文，下一次触控可重试。支持 AudioSession 的浏览器在用户开启声音时使用 `playback` 类型；不支持时维持 Web Audio 路径。
- 手势恢复尚未结束时，同一次操作的声音可等待恢复，最多保留 250 毫秒；过期、切后台、静音或再次中断均丢弃。禁止恢复时补播旧结果。切后台及上下文中断立即停止短音和收线循环，回前台尝试恢复，受浏览器限制时等下一次触控。
- 声音按钮开启成功播放不依赖资源下载的两音确认声；加载失败或浏览器拒绝播放不能伪装成功。只读 `getStatus()` 提供实际状态、资源数量及最近错误供检查，不增加玩家调试界面。
- 验证必须检查真实浏览器输出节点的 PCM 能量及静音后的零输出，不能把虚拟节点调度、截图和无报错当作已经听到声音。真机扬声器、系统静音和用户当前页面仍需单独确认。
- 断线的 `whooshShort` 从音源 0.20 秒处起播，避开约 0.20 秒的静音前导；持续 0.16 秒，短扫频从 620 Hz 下行到 180 Hz，首帧干脆断裂声保持同步。上鱼成功帧播放短落定声与 659 Hz（纪录 494 Hz）铃音，身份旋律仍在展示阶段一次播放。实体出水音从音源 0.12 秒处起播。参数依据音源 PCM 检查，不能仅以音源总时长估计有效片段。

### 声音按钮首次开启回归（2026-10-01，第四版）

第三版的恢复去重错误地复用了开场时被自动播放策略挂起的 `resume()` Promise，导致没有旧静音偏好的新页面点击声音按钮也无法播放。开场不得创建/恢复音频；首次触控和声音按钮负责启动。只要上下文尚未运行，每一次新的恢复调用必须立即调用 `resume()`，不能等待旧调用结束再重试；仅共享已建立的输出图和资源加载。旧请求的完成/清理不得清掉较新的恢复请求，静音意图继续优先。

验证增加：无存档/无声音偏好的冷启动、开场请求被浏览器一直挂起时点击仍可恢复、保存开启偏好后的刷新首次点击、关闭后开启及连续开关。用正式游戏按钮检查，不能只在诊断页先 `ensureAudio(true)` 后调用结果音效。

未知结果回落普通/空钩，异常时间不制造跳位，切换竿清空去重集合。镜头只在现有相机目标上叠加小幅运动，无新 draw call；每段声音节点数量有上限，不新增解码资源。测试覆盖分类、阶段去重、静音恢复、镜头边界/连续性、音效差异与资源存在性、应用事件接线和 Web Audio 执行。浏览器检查两种手机画幅的上岸、非鱼与失败镜头；真机需开启/关闭声音、切后台、听取不同结果与回弹的同步，并在低端设备对比帧率和音频占用。
