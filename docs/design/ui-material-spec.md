# UI柔和材质与通透层次

日期：2026-10-02。依据HANDOFF温暖欧卡休闲基调，延续button-states V2与responsive-ui；不新增装饰图。

## 目标与范围

缓解整片浅绿面板的实心、平板感。场景HUD呈现轻透的海盐色面材、柔和上缘反光和贴近轮廓的接触阴影；主按钮保持暖杏色软厚度；手记/结算/设置保持高不透明底色、正文可读。避免写实玻璃、高亮金属、白色大块底板、纹理噪点与循环扫光。

## 接口与输入输出

新增`ui-material.css`位于coastal-ui之后、reel-surface/button-states/responsive-ui之前。只修改面色、边线、阴影和必要的小范围backdrop-filter，不覆盖尺寸/位置/布局/业务状态。route-card、toolbar、zoom-group、aimCue、toast、fight-summary、actionCue、baitHint使用统一HUD层次；result/book/tripEnd/renderSettingsPanel使用稳定阅读层，内部卡片弱化重复边框。提示箭头使用同源面色，不能变成独立贴纸。

按钮在现有button-states层直接增加受光面渐变、柔和侧沿与底部内阴影，沿用已有语义和Hover/Toggled/Pressed强度；默认略透、主按钮和选中更稳定，禁用无亮面。核心fightHold及其SVG连续受力几何不修改。不存在新状态数据/存档或自动点击；未知状态沿用已有默认，图片/字体加载失败不影响材质。

## 性能与异常

不新增位图、SVG资源、3D draw call或shader；不新增动效循环、DOM测量、逐帧滤镜。仅toast与aimCue两个小区域支持blur(6px)，已有互斥逻辑避免同时大面积模糊；其他面板不增加背景模糊。无backdrop-filter支持或减少动态偏好时采用更不透明HUD面材，保持文字对比；模态不依赖模糊保证阅读。不能给祖先设置opacity，不能用伪元素覆盖输入。低端手机后续比较有/无小区域模糊时提示出现与拖动的帧时间，必要时关闭滤镜。

## V2：按角色分材质，减少重复底框

V1同一种浅绿渐变覆盖过多入口，导致主次仍不明确。V2把材质分成信息浮层（暖灰海盐/浅透）、操作承托面（更轻的冷青透明色）、工具按钮（清晰的海玻璃色）、主按钮（稳定暖杏厚度）、阅读层（暖灰纸感与浅绿边缘）。不靠添加更多高光、模糊或装饰来堆叠。

准备态未选中鱼饵直接落在承托面上，仅选中项有清晰底色与内沿；hover/pressed仍读原V2状态，禁用保持优先。结算操作图标取消独立镶框与金色小底块，选择说明去掉卡片底框和尖角，保留动作名/后果与原引导逻辑。阅读内卡改为更轻的分区，分隔线代替层层侧沿。所有尺寸、四向输入、可视高度与状态语义不变。

新增材料角色token、真实未选中入口规则和图标去框规则测试；原有小区域模糊数量不增加。V1验证记录保留为历史，当前以V2为准。

## 验证

Node解析真实CSS，检查加载层序、核心隔离、未改变布局/输入、文字不透明、各组材质覆盖、禁用/按压/选中规则保留、模糊作用域/回退、无新增持续动效。运行相关与全量测试及构建。遵循用户此前要求不进游戏、不使用Computer Use，颜色观感、场景对比和手机合成开销仍待实机验证，不用静态测试冒充视觉验收。
