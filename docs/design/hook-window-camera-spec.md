# 咬实后的水面取景规格

## 目标

鱼嘴真正咬住钩饵之后，让首竿玩家能先从浮漂、鱼线和竿身读懂“现在提竿”，再触碰右下操作区。9:16 近景中放大浮漂动作，但保留人物和竿线同框，不用新增文字、遮罩或大型提示。画面遵循 `HANDOFF.md` 的温暖简练基调。

## 数据与接口

- 不增加存档字段或随机抽取。`src/scene.js` 只读当前鱼口阶段、当前钓获类型、浮漂位置、镜头位置及现有竖屏状态。
- `src/fishing-camera.mjs` 的 `hookWindowCameraPose(waitingShot,bobber,forward,right,portrait)` 输入当前近景构图和真实浮漂坐标，输出 `{position,aim,fov}`；输入无效时返回原等待构图。靠近比例与视角定义在 `src/config/fishing-tuning.mjs` 的 `LURE_CAMERA_TUNING`。
- 镜头仅在近景、活鱼 `hooked` 且尚未搏鱼或收线时启动；鱼未碰钩、空钩、沉水物、俯瞰和结果阶段均不启动。手动近景环绕仍可用。

## 体验与边界

咬实前的鱼影观察镜头仍在 `nibble` 前退回等待构图。`readyAt` 后镜头沿既有视线渐进靠近浮漂，放大受力动作；没有一帧式变焦。玩家按下提竿后沿现有动作镜头自然进入搏鱼；失手或切换视角时平滑退出。镜头不修改浮漂物理、提竿时间窗与触控判定。

竖屏首竿落点在 390×844 与 320×568 均需让浮漂和人物留在画内，且浮漂比原等待镜头更易辨认。横屏只检查兼容，不以横屏构图决定参数。只做每帧少量向量运算，不增加网格、贴图、draw call 或 shader 采样。实际低端手机的连续帧率、触控与镜头眩晕感仍需真机验证。

## 验证

用 Node `node:test` 验证新镜头各钓点和画幅的投影、放大、退化输入与过渡连续性；在浏览器实际走首竿到咬实、提竿，复核竖屏构图和按钮可见。镜头的主观清晰度仍以玩家试玩确认。
