## 目标

遵循 `HANDOFF.md` 的欧卡休闲、干净温暖、非写实且非 Low Poly 基调。以水面、浮漂、人物与鱼线作为主体；准备时选饵/看线索，抛竿后等待水面，咬实后用同一个右下触控区提竿与收线。视觉风格是奶油纸面/陶瓷面、海盐绿、暖杏色主按钮、软倒角、克制高光和接触阴影。

## 输入、输出与接口

`src/ui/fishing-ui-state.mjs` 不依赖引擎或 DOM：

- `fishingUILayout({phase, aiming, pending, revealing})` 输入现有抛竿阶段/瞄准/未决抛竿/演出标记，输出 `{mode, canExpandRoute}`。
- `mode` 依次优先选择 result、landing、fight、strike、watch、aim、prepare。`pending.phase==='result'` 优先于旧 fight 标记；`revealing` 优先于 fight。存在未决抛竿时未知阶段按 watch，缺失输入按 prepare。只有 prepare 可展开路线。
- `selectedBaitCopy(id)` 输入当前饵 ID，输出 `{name, description, effect}`，内容来自 `BAITS`；未知 ID 回退首项，只影响文案。
- `src/app-final.js` 写入 `#game.dataset.uiMode`；`mountTripRoute.update(state, layout)` 收到相同布局，非准备态关闭原生 details。`mountSetupUI.update(state)` 同步名称/效果。
- 不新增存档字段，不调整随机鱼池、抛竿时长、提竿窗口、搏鱼物理或核心指针捕获。

## 资源与性能

- `src/coastal-ui.css` 是现有主题后的最终样式层，限制作用域为游戏/指定对话框，不污染独立画面参数面板。
- 运行插图 `public/assets/ui/shore-journal.webp` 为 imagegen 生成的透明手记与浮漂/贝壳装饰；只用于准备摘要和手记页眉。原图放 `assets_pipeline/ui/`，运行图 256×213、约 13.6 KiB、解码约 0.21 MiB。
- 不增加三维对象、draw call、shader 或后处理；新增面板避免全屏模糊。所有运行资源引用使用相对路径。
- 图片加载失败仍保留文字、触控目标和空间占位，不影响抛竿。

## 边界与异常

- 320×568 隐藏装饰与饵的长说明，仍显示饵名、选择态、轮次、进度、主操作；所有可触控入口至少 44px。顶部宽度不足不得挤掉按钮。
- 9:16 优先，底部/顶部读取安全区；桌面宽屏且高度充足时按 9:16 限制预览宽度（最大 480px），横屏仅兼容。临时状态文字与装饰不能接收 pointer；隐藏工作台和其他处理方式不得进入可触控/焦点顺序。
- 手记已打开时切页不重复创建 modal；实际搏鱼中拒绝打开，不清空或结算未决抛竿。
- 结果窗保留既有展开策略；去除旧伪元素/放大 canvas 的横向溢出，不能仅靠裁切隐藏文字。
- 存储失败仍通过准备态底栏显示已有提醒；本轮不变更保存规则。

## 2026-10-01：操作区内的即时引导

目标：手指操作附近能直接读懂当前动作；轻点纠错、抬竿收益不再另开浮层遮挡水面。

- `reelControlFeedback` 保留原输入与反馈字段，新增 `hint`、`showDirections`。`hint` 是最多两行的简短可见说明；`showDirections` 仅在 reel 模式为 true。strike 提醒咬稳后按住续收，retrieve 明确点一下收回，不显示上/下手势。reel 顺序仍为让线手势、抬竿后的回中、危险让线、松线先收紧、抬竿机会、普通收线；危险判断沿用原张力与松线逻辑。数据缺失返回普通收线说明，不修改搏鱼状态。
- 右下卡片增加 34px 说明区，112×112 连续手势按钮和底部动作标签在屏幕上的位置保持不变。说明、方向文字和插画全部 pointer-events:none；只有原按钮接收手势。不新增教学遮罩或阻断输入。
- 将 `#fightFeedback` 放入该说明区；纠错或抬竿结果出现时临时替代普通说明。没有反馈时恢复普通说明；进入 strike/retrieve 清空上一竿的反馈。`aria-live` 仅用于短暂反馈，普通逐帧说明不加入 live 区。
- 抬竿距离必须继续来自 `liftOutcomeText` 的实际净收益；不更改胜负、力度、时机、手势判定或存档。
- 320×568 保留两行说明和完整按钮，横屏仅做触控可达性检查。资源复用现有 ImageGen 手记插图与矢量线轮，不增加纹理、绘制对象或 shader。
- 验证：纯函数阶段/优先级/缺失与异常数值/无副作用单测；实际 DOM 结构与 strike 清空反馈回归；390×844、320×568 鱼口到搏鱼实画及提示/按钮边界检查，证据记录到 `docs/validation/ui-coastal-2026-10-01/report.md`。

## 2026-10-01：画幅对齐、钓获选择与悬浮操作台

目标：修正通知落在游戏区域之外，减轻钓获决策的信息密度，消除准备/瞄准/搏鱼等处整块发白的底板。

- 通知挂载到当前原生模态或 `#game`，不再挂到 body；以所在容器的可用宽度居中，左右至少 14px，宽度最多 320px，安全区继续保留。始终 pointer-events:none，文字由 textContent 写入。通知被替换或超时仍按原规则移除。
- 桌面宽窗口中的钓获窗仍遵循9:16游戏画幅，宽度最多440px且不超过按视口高度计算的游戏宽度减24px；手机两侧保持原安全边距，不跟随桌面留黑区扩大。
- 钓获窗以深海盐绿衬底、暖沙色文字、透明鱼体展示和轻分隔组织信息。首次仅显示鱼名、重量/长度/评级、当前约定、一个建议动作及其他选择入口；鱼种/搏鱼明细放原生 details 中。所有钓获（含首次/特殊/追踪）默认收起详情和替代动作，稀有身份由标签强调，不自动展开或替玩家处理。
- 处理按钮配对应矢量图标：放流鱼与水纹、鱼篓、收藏、手记/分析。图标 aria-hidden，按钮保留名称、明确后果与原 data-process 委托；展开后所有原动作仍可触控。推荐规则继续来自 catchActionPlan 和 processHint，不调整产出或容量。
- `src/ui/catch-choice-markup.mjs` 提供无 DOM 的动作按钮 markup 与约定文案；输入 action/推荐标记/后果或 trip.goal，输出转义的 HTML/简短文案。未知图标回退手记，缺失/完成目标说明自行选择，不修改状态。
- 钓获窗分成可滚动展示区与独立选择区；320×568 上主动作与替代入口可见。展开其他动作时选择区可内滚动、展示区可缩短；不裁切文字，不允许横向溢出。
- 小屏展开其他选择时收起鱼体插画，把鱼名与属性留在展示区；重新收起其他选择后恢复插画。只折叠表现，不清空钓获或停止保存。
- 准备工作台使用较深海盐绿小型路线区和悬浮选饵/暖杏色主按钮，减少白底面积；瞄准时取消整块面板，仅有紧凑深色提示和独立取消/确认按钮，提示不接收水面手势。搏鱼操作卡与顶部读漂提示也统一为有层次的海盐绿表面；保留既有 112px 手势位置。
- 共用按钮提供清晰主次、图标、边缘高光与接触阴影，按压反馈只在已有触控入口上，不新增 hover 依赖、三维绘制或大图资源。手记等阅读型模态使用柔和的浅沙纸色，内层列表减少重复底板。
- 验证：动作转义/图标回退/目标边界/默认折叠/显式处理不变/通知实际挂载的 Node 测试；320、390、430 竖屏与桌面宽屏的准备、瞄准、通知、钓获折叠/展开实画。详情见 `docs/validation/ui-refinement-2026-10-01/report.md`。新布局替代上述旧浅色底板和 notable 自动展开策略。

## 2026-10-01：提亮软边、动态图文与左上提示

目标：按玩家实画反馈提亮偏暗的海绿底板，消除锐利倒角与重复提示；恢复搏鱼时与真实状态相连的图文表达。

- 图文区域无指针输入；仅原112px线轮接收持续手势。320×568压缩示意高度，隐藏底部重复鱼饵说明，鱼饵名称与选择勾仍在按钮内；横屏兼容时限制卡片高度并隐藏示意；减少动态偏好时关闭装饰循环动画，几何数据仍真实更新。
