# 钓点履历与行程内容产出规格

日期：2026-10-02。状态：P0 履历已接入，P1 钓点准备流程实施规格与后续内容规划。承接 `HANDOFF.md`、`long-term-play-spec.md`、`trip-memory-spec.md` 和 `gameplay-config-balance-spec.md`。目标是让钓点成为玩家经历的容器，而不只是一组鱼池入口或解锁台阶。

## 产品目标

玩家在第 4、8、20 竿回看时，应能回答：这几竿主要在哪片水、这里实际遇到过什么、这次与上次有什么不同、下一竿想试什么。产出由**真实钓鱼事件 → 地点事实 → 可回看的片段 → 有条件的下一步**组成；无事发生的一竿允许保持安静，不补发虚构线索。上岸、沉水物、认得出的失手和安静都算一次地点经历；只有真实辨认的鱼能进入鱼种记录。

三钓点的内容母题沿用现有鱼池与环境：近岸浅滩看小鱼集群和轻提反应；栈桥外湾看木桩、谨慎鱼口与沉水物；外海深水看长线、深层鱼影与微光。母题只决定环境文案和可建议的试法，不能声称玩家已经看见未发生的事件。不同钓点有可区分的玩法条件、可回顾的事实和后续问题；不靠金币、装备等级或无限任务链填充。

## 内容产出结构与节奏

每竿先产生一份不可改写的事件原料（钓点、落点、鱼饵、水情、鱼影或鱼口、结果、玩家动作），再经三层编辑：**本竿事实**说明确实发生了什么；**地点对照**只在有前次真实记录时说出同地或异地的差别；**下一步**给一个可执行的小试法，并允许玩家直接休息。绝不按累计竿数自动发鱼、虚构稀有遭遇或把安静包装成新发现。相同事件连续出现时压缩叙述，优先呈现真正不同的落点、鱼种、回应或观察状态。

内容的三个时间尺度分别是本竿即时反馈、本轮四竿路线、跨轮的水域履历。第 4 竿应能复盘本轮去了哪里；第 8 竿应能看出至少一个地点与另一地点的真实差异（若事件相同，就诚实显示相同）；第 20 竿应形成几个可回看的地点片段，而非一串重复奖品。水域不因竿数“升级”：初访、再次尝试、确认一条水域观察这些章节必须由对应真实事件开启。后续可为每地配置少量观察问题、触发条件、验证条件和短句变体，配置只负责表达，不负责制造事件。

衡量内容质量时记录：20 竿内有多少不同的事实片段、连续重复文案的最长次数、玩家是否主动按线索换落点/饵/钓点、收竿后是否愿意再抛一竿。数值只用于试玩调优，不转成游戏内的刷竿任务。P0 先完成可信的数据底座与回看；条件化地点章节、对照文案和去重复规则归入 P1，在真实试玩样本上校准。

## P0 数据结构与接口

- `makeTripMoment` 增加稳定 `spot`、`zone`、`bait`、`weatherId`、`at` 快照；仅从本竿 `pending` 读取并校验。旧 moment 缺这些字段仍可显示原回顾，但不反推位置。`kind`、鱼身份、发现与问题的真实性规则沿用 `trip-memory-spec.md`。
- `save.waterChronicle` 是版本 1 的有界累计事实：`{version:1,total,lastOrdinal,spots:{[spotId]:{casts,outcomes:{landed,object,nearMiss,quiet},fish:{[fishId]:count},zones:{near,middle,far},recent:Moment[]}}}`。`lastOrdinal` 是已入账最大总竿序号，用于拒绝刷新/重复结算的旧竿。`total` 只计算此功能上线后已结算、且有合法地点的竿；每钓点 `recent` 最多 4 条，供个性化叙述。鱼种计数仅记上岸活鱼，沉水物与认得出的失手分别记在结果与最近片段里；总竿数 `save.casts` 仍是所有历史竿数的权威来源。
- `normalizeWaterChronicle(raw)` 对旧存档/缺字段/未知钓点或鱼/负数/非有限数字返回安全形态，不把 `log` 中的历史上岸鱼、旧文本或总竿数倒推成完整水域履历。若 `save.casts > waterChronicle.total`，界面说明“逐竿履历从此版开始”；旧存档不丢现有日志和本轮 moment。
- `addWaterChronicleMoment(raw,moment)` 为纯函数，只接收合法地点、已结算 moment 与未记录过的 castId；同一竿幂等，结果分流准确，最多保存每钓点四条近期片段，累计数字不受近期截断影响。引擎在 `processCatch` 成功、记录本轮 moment 的同一事务内写入；容量拒绝、非法处理、重复回调不写。新行程只清本轮 `moments`，不清长期履历。
- `spotChronicleView(save,spotId)` 输出地点卡所需的事实：已记录竿数、上岸/失手/安静/沉水物、真实遇见的鱼种数、最近一竿可核实的短句及下一步建议。地点内容种子位于 `src/config/gameplay/spot-content.json`，仅包含地点母题、未到访提示和可执行的初次落点/饵建议；不得以配置文案冒充真实发现。未知配置/钓点安全回退，不影响结算。
- `tripStory` 基于本轮合法且带钓点的 moments，按首次到访顺序给出一条简短路线与各地本轮竿数/真实结果；最重要的记忆卡标明它发生的钓点。旧本轮 moment 没有地点时省略路线，不写“全都在当前钓点”。

## 玩家可见流程

1. 准备态地图上的钓点显示“未到访 / 已在这里抛 X 竿”；未解锁仍只显示真实解锁要求。数字不鼓励刷竿，不给每日任务或奖励。
2. 手记的“水域”页在已有水情、观察与追踪信息前显示三张钓点履历卡：未到访先给地点母题和第一步；到访后展示累计竿数、真实上岸/失手等、最多一句最近经历。已开放的非当前钓点可一按前往；切换地点仍由玩家另行选落点与确认抛竿。
3. 四竿收竿页先给“本轮路线”，例如“近岸浅滩 2 竿 · 栈桥外湾 2 竿”，并在最重要记忆上标地点；下一步仍沿现有真实鱼讯/观察/追踪优先级，不因本轮竿数强行给一条任务。进入下一轮后长期钓点履历保留。
4. 显示口径区分“累计抛了几竿”和“此版已记录几竿”；没有完整旧数据时不说它从未在旧版本去过某钓点。上岸同鱼种多次可说“遇见 N 次”，不能凭两次钓获声称概率规律或同一个体。空钩不能变成鱼种线索。

## P1 钓点准备流程：从地点到下一竿

目标是让玩家点选钓点后，在同一个准备流程里知道“为什么试这里、这次准备怎么试、确认前还能改什么”。不增加任务、概率加成或自动抛竿。`spotChronicleView` 的 `next/action` 由最后一条**合法且带地点的真实结果**推导，输出为 `{spot,bait,zone}` 与一句可核实的建议：首次到访用地点配置；失手且保存了饵和落点时建议同条件再观察一次；平静或沉水物时建议换一个合法落点；上岸后建议换落点比较回应。若证据缺饵/落点，退回配置准备，不从当前选择猜测旧竿。建议只说“试试/留意”，不声称鱼仍在、概率更高或新线索已经出现。连续几次相同结果不能凭次数宣布已发现规律。

- 地图点选已开放钓点后，只变更地点与镜头焦点，并将下方现有路线卡临时转为“这片水的下一竿”准备摘要；摘要展示最近一次真实经历（或环境母题）、本次建议、可执行的饵和落点。取消瞄准后仍保留本次地点意图，改选其他钓点会更新摘要，均不扣竿。已有即时鱼讯/观察仍留在数据中，实际开始抛竿后恢复原有线索优先级。
- 手记地点卡为所有已开放钓点提供“按建议选落点”触控入口；点后先校验钓点仍开放、没有未决抛竿/结算，再切地点和饵，进入现有近景瞄准并将**合法预设**选到建议落点。玩家能继续点近/中/远、拖动微调、取消；只有再点独立确认按钮才调用 `makeCast`、增加竿数和抽取结果。无效建议安全退回正常准备，不半途消耗竿数。
- 选点时的水边观察文字只写地点环境与可尝试的观察方法；若有合法近期经历可准确提到最近结果。不能把配置中的生态母题写成已经发生的“大鱼绕行”“鱼群结集”等亲见叙述。旧存档只显示从此版开始记录的事实。
- UI 仅复用现有路线卡、手记、鱼饵选择和瞄准按钮，不增加场景资源或常驻遮挡。390×844、320×568 需检查切点后摘要、手记入口、近景落点与取消；两次确认原则和 44px 触控目标保持不变。

边界：锁定地点、未知地点、未决抛竿、正在结算、快速重复点击、配置缺失、旧 moment 缺饵/落点时不执行错误操作。Node `node:test` 覆盖四类结果的建议与回退，以及从手记/路线动作到瞄准的接线和不自动抛竿。实际手机双指、低端帧率和玩家是否理解“先准备、再确认”待真机试玩。

## P2 地图钓点选择标记：点选前就能判断

目标：玩家在 9:16 水面地图上不打开手记，也能看出三片水各自适合观察什么、是否开放、此版最近一次真实结果是什么，并有理由点选另一片水。地图标记只是**选择线索**，不是鱼群实时探测或收获概率预告；点选后的准备卡继续负责详细的饵和落点建议。

- `src/config/gameplay/spot-content.json` 每钓点增加短 `mapHint`（地点可尝试观察的对象）和单字 `mapGlyph`（岸边水纹、桥桩、深水微光的辨识符）。这两项仅为预写的地点特征，不声称玩家已经遇见鱼；配置校验要求三地唯一、非空、长度有界，失败时纯逻辑回退到中性短句与符号。
- `spotMarkerView(save, spotId, unlocked)` 是无 DOM 的纯函数，输入现有存档、合法钓点 ID、实时解锁布尔值，返回 `{id,glyph,hint,state,status,shortStatus,detail,aria}`；未知钓点返回 `null`。`state` 只能是 `locked / new / legacy / landed / near-miss / object / quiet`。锁点优先，不泄露结果；开放且此版无竿时，旧档用 `legacy` 而非伪称“未到访”；有竿时按该点**最后一条合法近期片段**定状态，不能用历史最好结果掩盖最近平静。如果累计有竿但近期片段缺失，保守使用 `legacy`。不根据累计竿数、鱼池权重或当前天气编造实时鱼讯。
- 地图标记包含固定的地点符号、名称、短状态词和 `mapHint`；选中态使用明确的“当前”标识。颜色只作辅助，文字必须能独立辨识。未解锁显示实际探索进度要求，按钮沿用既有触控逻辑；等待/瞄准仍沿用原阶段隐藏或禁用。无悬浮依赖，不增加动画脉冲、纹理、场景对象或 draw call。
- `src/ui/setup.jsx` 用同一视图渲染三地，`aria-label` 连续读出地点、开放状态、真实结果和地点提示。320×568 与 390×844 上三标记需同时可辨、最少 44px 可触控；不能盖住准备区与主要水面落点。若窄屏文字空间不足，压缩详情而保留名称和状态。选点只切地点和打开既有准备摘要，不抛竿。
- Node `node:test` 覆盖三地配置、锁点、首访、旧档、四类最近结果、结果顺序、损坏履历/未知地点，以及地图 JSX 对纯视图和可访问语义的接线。浏览器核对两种竖屏尺寸的普通/俯瞰准备态和点选反馈；真实手机触控遮挡和玩家选择理解度待试玩。

## 边界、性能与后续层次

- 未决抛竿刷新只沿用原快照，不能提前写履历。失败/空钩正常结算后写一次；`pending.spot` 缺失或未知时保持原结算但不写地点履历。`save.casts` 与履历的差额可出现，须诚实标识。
- 存档总量有上界：三地点 × 四最近片段 + 已知鱼种计数；不得把全部逐帧事件、完整截图或无限历史存入本地存储。手机 9:16 页面每卡内容可扫读、触控至少 44px；只增加 DOM 文本，不增加 3D draw call、纹理或 shader。
- P1：把“看见—怀疑—验证”的地点主题扩展到外湾和深水，条件与反馈经配置驱动；主题只能消费真实鱼影、鱼口、钓获或失手事件，不能按竿数自动升阶。P2：在已验证的地点记忆上给可感知的水面/声音变化和少量重逢片段，需另做低端设备预算与 7/30/90 活跃日内容消耗模拟。P0 不调整鱼池概率、钓组强度或收获经济。

## 验证

Node `node:test` 覆盖三钓点、跨轮累计、上岸/沉水物/失手/空钩、真实鱼种计数、重复结算、近期截断、损坏旧档、未知地点、旧 moment 路线降级，以及按钮点击只切地点不抛竿。构建和 `git diff --check` 必须通过。390×844 与 320×568 浏览器核对地图地点、手记卡和收竿路线；真机低端性能与自由试玩第 4/8/20 竿的自发意图仍需验证。
