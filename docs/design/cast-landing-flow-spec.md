# 抛竿落点选择流程规格

日期：2026-10-02。状态：P0 触控流程迭代。遵循 `HANDOFF.md` 的两段式抛竿：先看见落点预览，再由玩家确认抛竿。

## 2026-10-02：瞄准手势与入水交接

目标：消除水面微调时的落点跳跃与镜头追手，以及确认后预览圈突然消失的断层。三区域按钮仍是最轻的选点方式；微调与抛投形成同一个可追踪的位置。

- `src/cast-target.mjs` 的 `castAimDragPoint(spot,selected,startWater,currentWater)` 根据按下时的合法预览点与同一摄像机下的水面位移计算相对目标，再由既有可抛范围收束；无效水面/数值返回 `null`，调用方保留上一有效点。触控移动阈值为 7px，小于阈值的松手作为直接点选；按下本身不移动落点，拖动松手不再重投射。
- 场景在单指瞄准手势开始时固定该手势的射线摄像机；拖动期间取景盯住按下时的落点，手指移动不会反过来改变水面映射。松手后镜头继续平顺跟随新点。第二根手指加入时放弃该次单指选点，可双指缩放；两根手指都松开前不恢复选点。失焦、取消或切换阶段清理手势，不改变已确认抛竿。
- `src/cast-flight.mjs` 的 `castPreviewOpacity(stage,flightProgress)` 输出预览圈可见度：瞄准与抛投蓄力保持完整，浮漂起飞后逐渐淡去，入水前归零；非法进度安全隐藏。场景仅延用现有的预览圈/中心点网格，入水仍只触发原水花。`pending.castPoint` 是飞行和入水唯一目标；确认后的手势不再改变它。
- 性能：仅复用现有两枚预览网格，抛投约 1.8 秒内临时增加最多两个 draw call；每次手势仅保存一个摄像机快照，不每帧复制。390×844、320×568 竖屏核对手指微调、落点/人物同框、确认后预览至入水的连续性；低端真机触控与帧率待测。

边界：岸上触点、越界拖动、指针取消、镜头转场中操作、双指切入、快速确认/取消、刷新中的旧抛竿均不得改写随机结果、落点或竿数。Node `node:test` 覆盖相对位移、阈值/异常和淡出时间边界；继续跑完整测试、构建及视觉验证。

## 目标

让竖屏玩家不用在移动镜头里精确点水面，也能快速选择近、中、远水；已有水面点按和拖动继续用于微调。落点选择是一个清楚且可反悔的决定，不自动投竿、不改随机鱼池。

## 数据、接口和输入输出

- `src/cast-target.mjs` 新增 `castAimChoices(spot,point)`，从现有 `CAST_ZONES`、`castPreset` 及近岸首竿点返回三个固定顺序的有效落点选项，以及由真实预览点算出的选中区域。未知钓点返回空选项；有效钓点配上无效预览点时回退中段。所有选项必须通过现有水域可达验证；不另造一套落点规则。
- `src/app-final.js` 只在瞄准态显示三区域按钮。点区域按钮时更新当前 `aimPoint`，场景中的三维落点标记随之移动；点按或拖动水面微调时，区域高亮由实际 `aimPoint` 重新推导。预设按钮不触发抛竿、鱼池抽取、扣竿或保存新字段。
- 原 `confirmedCastPoint`、水面射线与 `makeCast` 仍决定最终落点。确认按钮在瞄准态显示实际目的地区域；确认仍是独立第二次点按。水情问题的指定落点若被改到别的区域，按自由抛竿处理。

## 交互和画面

1. 准备态点“选落点”或路线动作，平顺进入近景瞄准，默认落点立即可见。底部在取消和确认上方提供三个至少 44px 的近水、中段、远水触控区；进入前已有指定水情落点时对应区域高亮。
   近岸预设沿用首竿偏向人物左前方的可见落点，避免近景里被人物遮住；首竿默认点也要在 320px 宽屏内完整可见。
2. 点一个区域，预览点直接落在该水域的合法预设位置，选中态和顶部短句同步更新。玩家仍可点水面或拖动来选同一区域内更喜欢的确切位置；拖动不会抛竿。
   未调整时的底部提示指向三区域选择，调整后指向独立确认；水面微调后的文字、按钮和区域高亮须立即一致。
3. 选择后点“抛向近岸／中段／远水”才释放钓线。取消返回准备态，不消耗竿数。短屏上三个区域和取消／确认必须同时可见，不能挡住三维落点标记的主要观察区。

## 边界和异常

- 已抛竿、上岸处理、未知钓点、无有效目标时隐藏或禁用区域选择；镜头过渡时按钮可选择稳定的世界预设点，确认仍等待镜头就位。
- 水面微调可能把点压到可达圈边缘；区域高亮必须跟实际预览点一致。岸上/无效触点保持原点。快速重复确认仍只抛一次；取消排队确认仍有效。
- 仅增加 DOM 和 CSS，不增加三维模型、纹理、shader 或 draw call；390×844 与 320×568 核对主按钮、水域按钮和落点同框。低端真机还需检查触控与镜头帧率。

## 验证

`tests/cast-target.test.mjs` 覆盖三区域有效性、顺序、微调后高亮、未知钓点和坏点；运行完整 `npm test`、`npm run build`，并在两档手机竖屏走准备→区域选择→水面微调→取消／确认。
