# 鱼嘴与鱼饵挂钩资产规格

## 目标

每个可钓生物的 GLB 都提供明确的鱼嘴锚点，后续增加鱼种时无需用包围盒猜嘴的位置。三种鱼饵使用相同的钩尖锚点约定，在手机竖屏的浮漂近景中保持比浮漂更小的体量，并与钓线及鱼嘴共用一个钩点。

## 资产数据与坐标

- `public/assets/models/specimens/{id}.glb` 的根节点保持身体中心，Blender 中头朝 +X，导入 Three.js 后通过现有包装节点转为头朝 -X。每个可钓生物包含唯一的无网格节点 `MouthAnchor`，放在真实口缘或虾的摄食端；已有的 `{id}_Tail` 动画节点保持不变。锚点是资产局部坐标，不随体重、姿态或世界位置写死。
- `public/assets/models/fishing-details/bait_{id}.glb` 包含唯一的无网格节点 `HookAnchor`，位于实际钩尖。鱼饵与钩的制作尺寸以米为单位；三种游戏内鱼饵统一缩放到原资产的 0.72 倍，最大轮廓高不超过约 0.15 米，浮漂保持原尺寸。图鉴图可单独放大展示，不影响游戏内尺寸。
- 生成脚本是资产真源：`tools/generate_specimens.py` 和 `tools/generate_fishing_details.py` 导出到 `public/assets/models/`，同时维护源 `.blend` 和清单。不得仅在运行时伪造锚点而让原始 GLB 缺失。

## 接口与输入输出

- `fishMouthWorld(fish)` 返回当前鱼体世界空间的口缘。已加载 GLB 从 `MouthAnchor` 转换到鱼体根局部坐标；程序生成的备用鱼仍可使用 `userData.mouthLocal`。`alignFishMouth` 与 `attachHookToMouth` 保持原接口。
- `positionBaitOnHook(model, hookPoint, scale)` 以 GLB 的 `HookAnchor` 为准，把模型钩尖对齐浮漂局部钩点；漂的惯性偏移只平移目标，不改变鱼饵比例。鱼试饵、咬实和搏鱼共享该钩点。
- 从浮漂挂点切换到鱼嘴实体钩时，复用同一份鱼饵模型并重新挂载到实体钩，不新增可见副本。重新挂载后用 `HookAnchor` 对齐实体钩原点；返回浮漂时恢复局部挂点。异步加载回调必须读取当前挂载状态。
- 浮漂自身的下端配重珠应比鱼饵更小、颜色更沉，近景中不能看起来像仍挂在浮漂下的另一颗鱼饵。
- 锚点为无网格节点，不增加 draw call；在物理负载或动画旋转后，每帧仍从鱼体变换求实际口缘。
- 搏鱼浮漂的水平投影须对齐 `fishMouthWorld`，而非鱼体原点；实体钩、鱼饵和子线端点也都取该口缘，确保不同鱼体尺寸和朝向下都不会看似挂在背部。

## 边界与验收

- 缺失或重复命名锚点的新增 GLB 不通过资产测试。旧存档不保存锚点；加载旧存档时读取当前资产。异步模型不可用时继续使用已有程序备用鱼及其 `mouthLocal`。
- 对所有七种生物、三种鱼饵检查节点存在、有限坐标、口缘位于头端、钩尖贴合、模型预算与构建加载。不同姿态和尺寸下鱼嘴与钩点的误差应小于 1 毫米。
- 在 9:16 浏览器中检查浮漂、饵钩、鱼嘴的相对体量与咬钩画面；低端手机需观察新增资源是否造成帧率或内存回退。本轮不改变鱼种数值、存档或钓获概率。
