# 垂钓角色表情规格

## 目标与边界

让现有角色的眼、眉、嘴随真实垂钓动作表达期待、专注、吃力、喜悦和短暂遗憾。9:16 近景能辨认，幅度可适量夸张，保持温暖休闲风格；不增加表情弹窗、失败惩罚、声音/振动或强制脸部特写，不改变身体 IK、头部观察方向、鱼口窗口、计账和存档。

## 数据与接口

- `src/angler-expression.mjs` 的 `anglerExpressionTarget(context,now)` 为纯判定，输入真实 phase、pending、revealing、outcomeEvent、catchProcessEvent，输出 `{mood,eyeOpen,browLift,browTilt,smile,mouthOpen,mouthWidth,asymmetry}`。通道有限且有界，无效数值回落。杂物优先依据真实 catch 类型，不采用活鱼吃力表情。
- `createAnglerExpression().update(context,now,dt,reduced)` 连续缓入目标；断线惊讶采用较快过渡。等待时每约 4.8 秒一次短眨眼，咬实、吃力及惊讶时不插入眨眼，减少动态时关闭眨眼，保留静态表情。超长帧只有限追赶，不重复播放旧瞬态。
- `src/angler-face-rig.mjs` 的 `createAnglerFaceRig(headRoot)` 绑定现有 `Eye_white/Eye/Eye_highlight/Brow/Smile` 部件，支持 GLTF 名称后缀。眼部以共同中心压缩，眉毛绕各自中心轻转并升降；现有嘴网格替换为一个小圆管口型，原网格数量不增加。`apply(cue)` 更新位置/尺度/口型；`dispose()` 释放本实例新增几何，不能修改缓存源模型的共享几何或材质。缺部件时仍可更新其他部件。
- `installFishingArt` 提供 `setExpression(cue)` 并保存最近表情；模型异步加载后立即绑定/应用当前表情，不从默认微笑重新播放过期惊讶。脸部跟随现有 HeadPivot，不能漂出脸或帽子。

## 情绪与时序

| 场景 | 表达 |
| --- | --- |
| 等待/准备 | 松弛微笑，稀疏短眨眼 |
| 鱼影接近/试饵 | 眼睛略开、眉稍抬，专注观察 |
| 活鱼咬实 | 前约 280 ms 轻惊讶，随后期待/专注 |
| 搏鱼 | 按真实有效张力与负载收眉、略眯眼、绷嘴；松线时减轻 |
| 活鱼上岸/结果 | 逐渐舒展，嘴角上扬；首次/纪录/特殊来客更明亮 |
| 杂物上岸 | 单眉轻抬、短好奇口型，不咬牙或大笑 |
| 断线/脱钩 | 先睁眼/小张嘴，接着短遗憾，再回平静；空钩不做失败惊吓 |
| 放流/收纳/记录 | 放流柔和笑意，收纳满足，记录专注；杂物保持好奇 |

处理事件优先于上岸；失手仅消费 2.2 秒内的真实结果，新的抛竿排除上一竿的残留事件。恢复结果只保持当前表情，不重播咬钩/失手。后台时间跨过瞬态后按当前阶段收敛。

## 性能、异常与验证

不增加 mesh、材质、纹理、shader 或常驻 draw call；一次绑定只为两根眉和嘴分配独立几何。口型使用 147 个动态顶点及复用法线缓冲，不逐帧新建几何；口型未改变时不上传缓冲，统一保守包围球覆盖所有口型。模型绑定后总三角数仍在现有 24,000 三角预算内。加载失败维持原回退角色与业务流程，不抛错。

Node 测试覆盖各阶段、杂物、张力/松线、失败时序、旧事件、新抛竿、非法输入、连续过渡、眨眼与减少动态；加载真实 GLB 验证名称绑定、部件变化、嘴顶点/法线有限、源资产未被修改与生命周期。浏览器检查 390×844、320×568 实玩及独立动作预览，保存完整场景和必要的脸部细节截图。真机脸部可读性与低端设备连续 60 秒帧时间/内存仍待验证。
