# 浅滩轻提观察链规格

日期：2026-10-02。状态：P0 原型实施合同。本规格只覆盖一条短观察链，不代表 `long-term-play-spec.md` 的每日水情、个体记忆或完整配置系统已经实现。

## 目标

让玩家在现有的鱼影靠近与点按浮漂轻提鱼饵中，亲眼得到一条值得下一竿再试的线索。第一次有效回应形成猜想，第二次独立抛竿的有效回应支持它。它教会玩家读水面与主动回应，不增加必中鱼、奖励点数、额外操作模式或弹窗任务。

## 配置、数据与接口

- `src/config/gameplay/discoveries.json` 以纯 JSON 描述主题 ID、适用钓点/鱼饵、两个允许的真实事件、独立抛竿数门槛、结果与手记文案。第一条主题限定近岸浅滩和麦粒，鱼种未知时只说“鱼影”。配置不包含可执行代码；业务模块只识别 `live_approach` 与 `bait_follow` 两种事件。
- `save.discoveryNotes` 为可缺省的数组。单条 `{topicId,state,evidence,updatedAt}`；证据含稳定的 `castId,eventType,observedAt`。`castId` 取本竿序号和抛竿开始时间，不从鱼获日志反推。`state` 依实际证据单调流转：`seen → hypothesis → supported`；首次有效 `bait_follow` 可直接从无记录到 `hypothesis`。
- `recordDiscoveryEvidence(save,eventType,now)` 仅接受当前未结算的自然鱼口、有效活体对象、配置条件与有限时间戳。`recordVisibleApproach(save,view,now)` 再检查近景、页面可见和无覆盖弹窗，才登记真实靠近；`bait_follow` 只在现有 `teaseBait` 成功后登记。返回本次状态变化或 `null`。同竿同事件去重；同竿反复轻提不能构成第二证据。完成后不持续堆积证据。
- `discoveryThread(save)` 只对未完成且仍有效的主题给出一个方向，使用真实的选点、换饵或瞄准动作；`discoveryResultLine(pending)` 给本竿一次结果回响；`discoveryJournal(save)` 供手记展示。以上业务计算不依赖 Three.js、DOM、设备当前时间或随机源。

## 输入、输出与玩家体验

1. 在近岸使用麦粒时，真实鱼影进入近景可见的靠近阶段，手记可记下“看见”。若玩家当时在顶视、页面隐藏或覆盖式弹窗中，不声称已亲眼看见；稍后实际轻提仍可留下更强的回应证据。
2. 玩家在有效靠近/试饵阶段点按浮漂，现有轻提动画与鱼影跟近发生；手记进入“待再试”，处理本竿时用一句话回响，并在准备态建议用同条件再观察一次。玩家可以自由换点、换饵或不轻提。
3. 不同抛竿再发生同样的真实回应时，手记进入“观察支持”。表述是本游戏水域里的可重复习性，不推断所有鱼种或统计概率；不保证下一竿钓获。
4. 下一竿路线优先级为失手即时鱼讯、未完成的亲见观察、新水域、追踪个体、旧线索。一次只置顶一个方向；已支持的观察回到手记，不长期占据路线卡。
5. 空钩、失手和放流都可保留在失手前真实发生的观察；完全没有相关事件的空钩不能产生证据。结果反馈只回响本竿真实的状态变化一次，不改变原钓获处理、鱼池、鱼口、搏鱼和奖励。

## 边界与异常

- v1/v2 旧存档缺少 `discoveryNotes` 时初始化为空；保留所有既有字段和未决抛竿，不把历史钓获或旧 `clues` 转成亲见证据。不提升存档版本。
- 非法主题、事件、钓点、鱼饵、时间、沉水物、非自然鱼口、无当前抛竿、已结算、重复事件均安全忽略。当前抛竿若重新加载，只沿用已存证据和原开始时间。
- 状态不能因后续没有再见到鱼而倒退；结果页重复处理不得再次播报或增加证据。配置内容变动后，未知旧主题在存档中保留但不推荐。
- 手记和路线只增加文字与现有动作，无新模型、纹理、draw call 或复杂 shader。390×844、320×568 竖屏检查准备、等待、结果回流和手记；横屏仅查可用性。低端真机帧率及玩家是否自发再抛需另行实测。

## 验证

Node `node:test` 覆盖正常三阶段、两竿支持、同竿和重复结果幂等、失手/空钩/挂物、错条件、旧存档、未知配置与路线优先级。构建后检查 JSON 打包和触控入口；视觉验证只说明当前可观察到的画面，不替代真人十分钟试玩。
